# 從數據到決策

數據不會自己說話——同一張報表可以支持相反的結論。這篇是解讀紀律：怎麼從數字走到「所以我們要改什麼」，而不掉進常見的統計陷阱。

## 假設驅動，不是撈魚

分析從假設開始，跟玩測同一條紀律（見 `../../../planning/game-design/references/playtest-hypothesis-and-metrics.md`）：

1. **寫下假設**：「第 3 關流失高是因為難度尖刺」。
2. **推論可觀察後果**：若為真 → 第 3 關死亡數應顯著高於前後關、且 quit 集中在多次死亡後。
3. **查數據驗證**：成立 → 進一步用玩測看「玩家卡在哪個具體位置」；不成立 → 換假設（可能是關卡太長、或獎勵不值）。

反面是**撈魚（data dredging）**：在幾百張圖表裡翻「有沒有什麼有趣的」——翻久了必然撈到隨機雜訊當發現。探索可以，但探索得到的是**新假設**，不是結論；用新資料再驗一次才算數。

## 比較要有對照

「改版後 D1 從 35% 升到 38%」——先別開香檳：

- **跟誰比**：同期是否有活動、假期、買量波動？節假日的留存天然不同。
- **cohort 對齊**：只比同版本、同來源、同時段進來的玩家（見 `telemetry-funnels-retention.md` 的 cohort）。
- **樣本量**：每組幾百人時 3% 的差可能是雜訊。小樣本看趨勢方向，別對小數點做決策。
- **A/B 測試**（若流量夠）：同時段隨機分組是最乾淨的對照——參數做成 config 遠端可切（見 `../../../architecture/game-architecture/references/data-config-driven.md`），A/B 才做得起來。

## 數據 × 玩測的互補循環

| | 遙測（量化） | 玩測（質化） |
|--|------------|------------|
| 強項 | 哪裡、多少人、多常 | 為什麼、什麼感受 |
| 盲區 | 動機、情緒、誤解 | 樣本小、情境失真 |

標準循環：**遙測發現異常（第 3 關 quit 率 2 倍）→ 玩測解釋原因（教學漏教了某機制）→ 修改 → 遙測驗證（quit 率回落）**。只用其中一邊：遙測會修錯方向，玩測會漏掉規模。

## 解讀陷阱

- **相關 ≠ 因果**：「用了衝刺的玩家留存高」——可能是衝刺讓人留下，也可能是本來就投入的玩家才會學衝刺。要因果，用 A/B 或至少對齊 cohort。
- **倖存者偏差**：「第 10 關的玩家評價都很好」——會走到第 10 關的本來就是喜歡的人。看倖存者的同時看流失者的最後足跡。
- **辛普森悖論**：整體上升但每個分組都下降（或反過來）——組成比例變了。重要結論多切一個維度驗算（平台、來源、新老）。
- **目標成為指標即失效**（Goodhart）：拿 D1 當唯一 KPI，就會長出「用簽到彈窗騙 D1」的設計——指標成組看、對照玩家長期價值。
- **儀表板疲勞**：報表建了 30 張沒人看。核心儀表板 ≤ 10 個數字（漏斗、留存、DAU、崩潰率、經濟平衡），每週固定看；其他按問題臨時查。

## 決策的最後一步

每次分析收尾三行，寫進團隊可見的地方：

```
發現：第 3 關 quit 率 18%（其他關 6-8%），集中在 3 次死亡後
解讀：難度尖刺假設成立，玩測確認是紅色炸彈的視覺預警不足
行動：加大炸彈預警動畫，下版驗證 quit 率目標 < 10%
```

沒有「行動」欄的分析是消遣；沒有「下版驗證」的行動是許願。

## 常見陷阱

- **看數據代替做決定**：數據縮小選項，決定仍是設計判斷——「數據說要這樣」常是不敢負責的修辭。
- **每個雜訊都反應**：日報表天天抖，追著日波動改遊戲會把方向盤打爛。看週趨勢、設變化閾值。
- **分析私有化**：結論留在分析者腦中或聊天記錄裡，三個月後同一個問題再查一遍。用上面的三行格式歸檔。
