# Regex 機制與坑

大部分「regex 不對」不是符號記錯，是**沒搞懂引擎怎麼吃字元**——貪婪、邊界、群組。這篇是這幾個機制的決策與最常踩的坑。

## 貪婪 vs 惰性：預設會吃過頭

量詞（`*` `+` `?` `{n,m}`）**預設貪婪**——先盡量多吃，再回退到剛好能 match：

```
輸入：<a><b>
<.+>     → 貪婪：match 整個 <a><b>（.+ 一路吃到最後一個 >）
<.+?>    → 惰性（加 ?）：match <a>（吃到第一個 > 就停）
<[^>]+>  → 更好：字元類直接排除 >，不靠回溯，最快最穩
```

**決策順序**：能用**精確字元類**（`[^>]`）就別用 `.` + 惰性——字元類不需要回溯、意圖也更清楚（也避開 `safety-backtracking-and-flavors.md` 的回溯地雷）。惰性只是「少吃一點」，不是「更精確」。

## Anchor 與邊界：沒錨點就到處 match

- **`^` `$`**：綁行首/行尾。少了它，pattern 會在字串**任何位置**找到就算數——`\d{4}` 想抓「整串是四位數」卻 match 到 `12345` 裡的 `1234`。要「整串符合」就 `^…$`。
- **`\b` 單字邊界**：抓完整單字。`cat` 會 match `category` 裡的 cat；`\bcat\b` 才是獨立單字 cat。
- **多行模式**：`^ $` 預設綁整個字串頭尾；開 multiline flag（`m`）後才綁每行頭尾。搞混會「怎麼只 match 到第一行」。
- **`.` 不吃換行**：預設 `.` 不含 `\n`；要跨行用 dotall/single-line flag（`s`）或字元類 `[\s\S]`。

## 字元類的坑

- **`.` 幾乎總是太寬**：它吃「除換行外任何字元」——你要的通常更窄。明確列 `[a-z0-9_]`。
- **類內的特殊字元規則不同**：`[.]` 裡的 `.` 是字面點（不用跳脫）；`-` 要放頭尾或跳脫（`[a-z-]`）否則變範圍；`^` 放開頭是「取反」（`[^…]`）。
- **`\d` 不只是 0-9**：在 Unicode 模式下某些 flavor 的 `\d` 會 match 其他語系數字——要嚴格用 `[0-9]`（見 flavor 篇）。

## 群組：捕獲、非捕獲、命名

- **`( )` 捕獲群組**有成本與副作用：它佔用編號、被 replace 的 `$1`/`\1` 引用。**只為分組（配 `|` 或量詞）而不需要抓內容時，用 `(?:…)` 非捕獲**——省編號、意圖清楚、通常更快。
- **命名群組 `(?<year>\d{4})`**：多個群組時用名字而非數字，改 pattern 不會因為插入一個群組就把後面 `$1$2` 全錯位（可讀性見 `design-when-and-readability.md`）。
- **backreference `\1` / `(?P=name)`**：match「和前面群組相同的內容」（抓重複字、成對引號）。但 backreference 會讓引擎無法用高效演算法、是回溯熱點——需要才用。

## 跳脫：該跳的沒跳

- **要 match 字面的 metacharacter 要跳脫**：`. * + ? ( ) [ ] { } ^ $ | \` 這些直接寫是特殊意義，要字面得 `\.`。抓 IP、版本號、路徑時最常忘記跳 `.`——`1.2.3` 的 `.` 沒跳會 match 任意字元。
- **動態組 pattern 要跳脫使用者輸入**：把使用者字串塞進 regex 前用語言的 `escape`/`quote`（`re.escape` / `Pattern.quote` / `RegExp.escape`）——否則使用者輸入 `.*` 會變成 pattern，功能壞掉甚至變 ReDoS 入口（見安全篇）。

## 常見坑速查

- **貪婪吃過頭**：`<.+>` 吃整行——用 `[^>]+` 精確字元類，不是只加 `?`。
- **沒 anchor**：想「整串符合」卻 match 到子字串——`^…$`。
- **`\bcat\b` 忘了邊界**：match 到 category——要獨立單字加 `\b`。
- **`.` 當萬用**：太寬、還是回溯地雷——明確字元類。
- **忘跳脫 `.`**：抓 `1.2.3`／網域，`.` match 到任意字元——字面點 `\.`。
- **每個 `()` 都捕獲**：編號錯位、變慢——純分組用 `(?:…)`。
- **多群組用數字**：插入群組後 `$1$2` 全錯位——命名群組。
- **使用者輸入未 escape 就組 pattern**：功能壞 + ReDoS 風險——先 escape。
