# 動畫 / VFX 技術規格與效能

特效與動畫是效能預算的大戶（overdraw、蒙皮、每幀配置三面夾擊）。規格從目標平台的實測預算反推（方法同 `art-tech-specs.md`），數字填進 content-production 的規格表。

## 粒子預算

- **同屏粒子總數上限**：目標平台實測定（行動千級、PC 萬級量級，profiler 為準，見 `../../../tools/game-tooling/references/perf-measurement-first.md`）——並拆到「單一特效上限」與「同屏總帽」兩層，單發合格疊起來爆掉是常態。
- **Overdraw 是真正的殺手**：粒子多半是半透明大面片，疊層填色遠比粒子數痛（見 `../../../tools/game-tooling/references/perf-common-hotspots.md` 的渲染熱點）——規格限制「單特效最大面片尺寸與疊層數」；貼圖裁緊（alpha 邊緣不留大片空白）。
- **距離分級**：遠處特效減量/減尺寸/換簡化版（LOD 思維，見 optimization-playbook）——螢幕上 20px 的爆炸不需要 200 顆粒子。

## Flipbook（序列幀）與貼圖

- **何時用 flipbook**：複雜運動（火、煙、爆炸）烘成序列幀，比即時模擬便宜且藝術可控——代價是貼圖記憶體，尺寸 × 幀數要進規格。
- **幀數與尺寸取捨**：4×4 到 8×8 圖集是常見甜蜜點；幀間插值（motion vector / frame blending）可用一半幀數達到平滑。
- **共用圖集**：通用粒子貼圖（煙、光點、碎片）進共用圖集（`_shared`，見 `content-asset-conventions.md`）——每個特效自帶一張 2048 貼圖是記憶體災難。

## 動畫資產的效能

- **骨骼與蒙皮預算**：按同屏數量分級（主角 > 精英 > 雜兵，見 tech-art-specs 的骨骼段）；大量單位考慮頂點動畫貼圖（VAT）或簡化骨架。
- **動畫壓縮**：取樣率與曲線容差進規格——肉眼無差的壓縮常省 50%+ 記憶體；但主角手部/面部這種貼臉部位壓縮要保守。
- **遠處降頻更新**：遠處單位的動畫每 2-4 幀更新一次（時間分片，見 optimization-playbook 的降頻）——鏡頭外的直接暫停。

## Pooling 與生命週期

- **特效一律走物件池**（見 optimization-playbook 的池化）：戰鬥中即生即滅的東西 spawn/destroy 是 GC spike 之源（見 common-hotspots 的每幀配置）。
- **池預熱到峰值**：最吵場景的同時特效數就是池容量，載入期填滿。
- **生命週期明確**：每個特效有硬性最大存活時間——「忘了關的循環特效」累積到場景裡，效能慢性失血。
- **發射器與粒子分開回收**：發射器停止後殘存粒子要自然走完消散段（見 `anim-vfx-design.md`），不是整組瞬間消失。

## 規格表範例欄位

| 欄位 | 範例 |
|------|------|
| 特效等級 | S（絕招）/ A（技能）/ B（普攻）/ C（環境） |
| 粒子數上限 | S:300 / A:150 / B:50 / C:30 |
| 最大面片尺寸 | 螢幕高的 50% / 30% / 15% / 10% |
| 貼圖 | 共用圖集優先；專屬貼圖 ≤512、flipbook ≤2048 |
| 存活上限 | 一次性 ≤3s；循環型必須可被系統強制回收 |
| 燈光 | 即時燈 S 級限 1 盞，其餘用假光（貼圖亮片） |

（數字是量級示意，照 tech-art-specs 的反推法用自己平台的實測換掉。）

## 驗收

- [ ] 單發：三段結構完整、與音效同幀（逐幀工具驗，見 `../../../tools/game-tooling/references/debug-time-control.md`）
- [ ] 連發與疊加：最吵場景 profiler 過預算、畫面仍可讀（見 visual-readability 的高峰測試）
- [ ] 池行為：高峰後記憶體回落、無殘留循環特效（watch 面板盯活躍特效數，見 debug-toolkit）
- [ ] 遠距與鏡外：LOD 生效、鏡外暫停

## 常見陷阱

- **只驗單發**：單發 60fps、十個同放 20fps——驗收永遠含疊加場景。
- **特效自帶即時燈**：每個爆炸一盞即時光，同屏十盞直接跪。即時燈是 S 級特權。
- **循環特效無人回收**：掛在角色身上的 buff 特效在角色死亡後留在原地——生命週期綁定要進事件表（見 audio-implementation 的同一張表）。
- **規格只管美術不管程式**：粒子數合格，但每幀在 update 裡 new 彈道物件——動畫/特效的程式側同樣受 data-oriented 紀律管（見 `../../../architecture/game-architecture/references/data-oriented-layout.md`）。
