# 音效設計

音效的第一職責是資訊：玩家閉著眼睛也該知道「打中了沒、撿到什麼等級的東西、危險從哪來」。這篇講怎麼從遊戲事件建出音效庫。

## 事件清單法

音效清單不是憑空列的，從三個來源反推：

1. **玩家動作**：每個輸入動作至少一個聲音（移動、跳躍、攻擊、揮空、受擊、死亡）——揮空與命中分開做，是打擊感的地基（見 `../../game-design/references/feel-impact-feedback.md`）。
2. **系統事件**：拾取、升級、任務完成、警告、UI 操作——資訊型音效，重點是**可辨識**：升級音永遠是那個音。
3. **世界環境**：ambience（環境底噪）、互動物件、腳步（按地面材質分）——存在感型音效，重點是不搶戲。

清單做成表（配 `content-asset-conventions.md` 的規格表），欄位：事件、優先級、變體數、是否 3D、掛哪條 bus。

## 分層設計（Layering）

重要音效由多層合成，各層各司其職：

```
爆炸 = 瞬態層（punch，前 50ms 的衝擊）
     + 主體層（boom，中頻能量）
     + 尾巴層（碎片、回聲，空間感）
     + 甜味層（低頻 sub，體感）
```

- **瞬態決定「打擊感」**：前 20-50ms 的 attack 快不快，決定音效「脆不脆」——回饋音的瞬態要硬，環境音要軟。
- **分層的好處**：換一層就是新音效（同主體換尾巴 = 室內/室外版本）、強度分級只調層的組合（小爆/大爆共用素材）。
- 重要度對應層數：核心動作音 3-4 層，UI 點擊 1 層就夠。

## 變體防重複

同一個音連續播 20 次，再好聽也變噪音。防重複的標準組合：

- **每個高頻音效 3-5 個變體**（腳步、攻擊、命中這種每分鐘幾十次的，變體是必需品不是加分）。
- **隨機化音高與音量**：每次播放 ±5-10% pitch、±2-3dB volume——便宜且極有效（實作見 `audio-implementation.md`）。
- **round-robin 或隨機不重複**：避免同一變體連續兩次。
- 判斷變體數的方法：把該音效所在的一分鐘 gameplay 錄下來聽——聽得出重複就加變體。

## 與手感的掛鉤

- **同幀觸發**：命中音必須與 hitstop、閃白同一幀（見 impact-feedback 的同步原則）——音效慢兩幀，「打擊感很虛」的鍋常在這。
- **強度分級一致**：輕攻擊/重攻擊/暴擊的音量與音色階梯，跟視覺回饋的階梯對齊——全都最大聲等於沒有層次。
- **負回饋也要有聲音**：格擋、無效攻擊、資源不足的「錯誤音」——沉默會讓玩家以為沒按到。

## 常見陷阱

- **音效當裝飾做**：先做環境音與音樂、核心動作音最後補——順序反了，回饋音是 gameplay 的一部分，白盒期就該有佔位音。
- **試聽用單發、遊戲裡連發**：單發很棒的音，戰鬥裡每秒五次就是災難。驗收用實際 gameplay 錄音聽。
- **所有音都想存在感**：每個音效都做得又滿又亮，疊起來糊成牆——資訊型的亮、存在感型的收，見 `audio-mixing-loudness.md` 的層級。
- **佔位音用太久**：整個團隊習慣了佔位音，換正式音效時手感「變了」被抱怨——重要回饋音早點定稿。
