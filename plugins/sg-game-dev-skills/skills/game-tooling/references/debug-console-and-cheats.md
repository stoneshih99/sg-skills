# 開發者控制台與作弊指令

測試迭代的速度 = 「到達想測情境」的速度。每次都手動玩五分鐘才到測試點，一天下來浪費的時間比寫控制台還多。作弊指令不是奢侈品，是開發基礎設施。

## 兩種形式

**文字控制台**（打字執行）：
- 適合：參數化指令（`give gold 500`、`goto level 3`）、指令多的專案。
- 按 `~` 或三指點擊呼出，含歷史記錄與自動補全（做一半也好用）。

**除錯面板**（按鈕/滑桿選單）：
- 適合：高頻操作（無敵開關、跳關按鈕）、行動裝置（打字困難）。
- 做成可捲動的分類選單，一鍵執行。

小專案：先做面板（半天）；指令超過 20 個再補文字控制台。兩者共用同一套指令註冊。

## 指令註冊設計

指令做成資料註冊，不要 if-else 串（與 `../../game-architecture/references/data-config-driven.md` 同一精神）：

```
register_command("give", args=[item_id, amount], handler=cmd_give,
                 help="give <item> <n> — 給予道具")
register_command("god",  args=[], handler=toggle_god, help="無敵開關")

on_console_submit(text):
    cmd, args = parse(text)
    commands[cmd].handler(args)     # 找不到 → 印 help 與相近指令
```

- 新指令一行註冊，任何系統都能自己加。
- `help` 自動列出全部指令——指令的可發現性決定它會不會被用。

## 常備指令清單

建專案時照抄，各系統陸續補：

**狀態類**
- [ ] `god` — 無敵
- [ ] `noclip` — 穿牆飛行（卡地形檢查的救星）
- [ ] `kill_all` / `kill target` — 清場
- [ ] `heal` / `sethp <n>`

**資源類**
- [ ] `give <item> <n>` — 給道具 / 貨幣
- [ ] `unlock_all` — 解鎖全部（技能/關卡/圖鑑）
- [ ] `set_progress <flag>` — 設任務/劇情旗標

**場景類**
- [ ] `goto <level>` — 跳關（**最高頻**，最先做）
- [ ] `spawn <enemy> [n]` — 生成敵人（測遭遇平衡）
- [ ] `reload` — 重載當前關卡
- [ ] `save` / `load <slot>` — 任意點存讀（測存檔系統）

**觀察類**
- [ ] `debug <layer> on|off` — 切 debug draw 分層（見 `debug-draw.md`）
- [ ] `timescale <x>` — 時間縮放（見 `debug-time-control.md`）
- [ ] `stats` — 顯示效能/實體數面板

## 測試組合技

- **玩測 build 留作弊**：玩測員卡死時主持人能救場、能快速跳到要測的段落（配 `../../game-design/references/playtest-running-a-session.md` 的救援規則——救援用跳關，不用口頭提示）。
- **情境書籤**：`setup <name>` 一鍵佈置測試情境（波次 3 + 半血 + 特定裝備），回歸測試不用手動重擺。
- **啟動參數**：`--goto level3 --god` 讓你重啟即達測試點，配熱重載體驗更佳。

## 安全與紀律

- **發佈版剝離或上鎖**：編譯開關移除，或至少要求啟動密令。上架版被玩家翻出作弊選單是事故。
- **作弊要標記存檔**：用過作弊的存檔打標記，避免污染平衡數據與成就。
- **指令也是 API**：跳關指令繞過的初始化流程，正式流程也可能繞過——作弊指令炸掉常常是真 bug 的預告。

## 常見陷阱

- **捨不得花半天建**：「先手動測，之後再做」——之後永遠不會來，時間持續流失在重複操作上。
- **指令沒有 help**：三週後連自己都忘了有什麼指令。註冊時強制要求 help 字串。
- **跳關後狀態不完整**：`goto` 沒帶上該有的進度旗標，跳過去的關卡邏輯壞掉，反而以為遊戲有 bug。跳關指令要負責把前置狀態補齊。
