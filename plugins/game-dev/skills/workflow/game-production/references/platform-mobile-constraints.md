# 行動平台約束（Mobile Constraints）

手機不是「小螢幕的 PC」——觸控、發熱、電池、隨時被中斷、商店審查全是硬約束，而且多數要在**設計期**吃進去，上線前才補救的成本是重做級。這篇管引擎中立的設計決策；引擎層落地（平台設定、目標幀率 API）見 **sg-unity-dev-skills** 的 build-platform。

## 觸控輸入：為手指設計，不是為游標

- **最小觸控目標 44pt（iOS）/ 48dp（Android）**：視覺可以更小，但熱區不行——「隱形熱區比圖示大」是常態手法，不是作弊。
- **控制方案選型**：

| 方案 | 適合 | 代價 |
|------|------|------|
| 虛擬搖桿 | 即時連續移動（動作類） | 遮擋畫面、無觸覺回饋、精度差——判定容錯要放大 |
| 點擊/拖曳直接操作 | 策略、休閒、卡牌 | 觸控的主場，能用就優先 |
| 手勢 | 輔助動作（縮放、快捷） | 可發現性差——**不可承載核心高頻操作** |

- **手指會遮擋螢幕**：關鍵資訊別放拇指熱區下方；慣用手差異要嘛對稱設計、要嘛提供鏡像選項。
- **沒有 hover**：tooltip 語意用長按替代，但長按有延遲成本——高頻操作別掛長按。
- **時序容錯放寬**：觸控的取樣與延遲都比實體鍵差——input buffer 與判定窗比 PC 版寬（意圖分層與容錯見 `../../../architecture/game-architecture/references/system-3c.md`）。

## 效能：發熱與電池是預算，不是事後題

- **行動效能的真相**：持續負載 → 發熱 → 系統降頻 → FPS 跳水。冷機測到 60fps 不算數，**跑 30 分鐘熱飽和後還在的才算**——量測紀律（`../../../tools/game-tooling/references/perf-measurement-first.md`）在行動平台要加「熱飽和場景」。
- **品質檔位資料驅動**：低/中/高檔位 = 解析度縮放 × 特效密度 × 陰影 × 模擬頻率的組合表（`../../../architecture/game-architecture/references/data-config-driven.md`）——同一套檔位系統，PC 的畫質選單直接複用（見 `platform-pc-constraints.md`）。
- **發熱降級三段**：溫→降解析度/粒子；熱→鎖 30fps；臨界→關非必要系統。降級要**漸進、可回升、帶遲滯**——溫度在門檻附近抖動時畫質跟著抖是最糟體驗。
- **30 vs 60 fps 是類型決策**：預設 30（電池與熱空間翻倍），只有對時序敏感的類型（動作、音樂）才付 60 的熱成本。
- **電池黑名單**：常開網路輪詢、GPS、防睡眠鎖、背景不暫停——每一項都會出現在商店評論。

## 生命週期：隨時被打斷、隨時被殺

- **電話/通知/切走隨時發生**：pause 事件觸發「暫停模擬 + 靜音 + 自動存檔」三件套——「切回來進度沒了」是一星評論主力。存檔時機的引擎落地（行動平台等不到 quit 事件）見 **sg-unity-dev-skills** 的 asset-save-persistence。
- **背景的 app 隨時被系統殺掉且無通知**：重要進度不能只活在記憶體。
- **回前台的恢復是設計題**：重建連線（斷線重連見 `../../../architecture/game-architecture/references/net-protocol-and-connection.md`）、離線時間差結算（放置類的核心循環）、重取音訊焦點。

## 螢幕與 UI

- **safe area 是硬規則**：瀏海、圓角、手勢條——UI 錨定 safe area 而非螢幕邊緣（適配規格見 `ui-tech-specs.md`）。
- **直式 vs 橫式是設計決策不是 checkbox**：雙向支援 = 兩套版面的成本；鎖單向要跟類型慣例（休閒直式、動作橫式）。
- **長寬比比 PC 更碎**：手機 18:9~21:9 加平板 4:3——錨定佈局第一天就做，後補破版是全 UI 重排。

## 商店審查（硬規則，條文變動快）

- **iOS**：隱私標籤必填；**有帳號註冊就必須有帳號內刪除**；追蹤要 ATT 授權彈窗。審查天數要排進發版時程（`build-release-checklist.md` 的平台提交節）。
- **Android**：target API 每年抬升（不跟就被下架）、64-bit 必須、AAB 格式。
- **兩平台皆有**：內購揭露、未成年保護。條文年年變——本篇只固定「哪些類別必查」，具體條文發版前查當年官方清單。

## 常見坑

- **PC UI 直接縮小**：觸控目標過小、字太小——為觸控重設計，不是等比縮放。
- **只在新旗艦機測**：多數玩家在 2-3 年前的中端機上——測試矩陣要含低端機，發熱降頻在那裡才現形。
- **效能只測冷機**：上架後「玩十分鐘就掉幀」——熱飽和測試進驗收清單。
- **存檔掛 quit 事件**：行動平台等不到——掛 pause。
- **忽略 safe area**：瀏海吃掉血條、手勢條蓋住按鈕。
- **提交當天才看審查規則**：帳號刪除這種缺項是整版打回，來回一次一週。
