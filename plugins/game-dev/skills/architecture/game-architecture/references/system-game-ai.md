# 遊戲 AI 系統（Game AI）

Gameplay AI 的架構：感知 → 決策 → 執行三層，加上動作遊戲特有的群體協調與表演性。先立一個方向性原則：**遊戲 AI 的目標是「可讀且好玩」，不是「聰明」**——玩家要能讀懂敵人想幹嘛（才有應對的樂趣），太聰明的 AI 體感等於作弊。

## 分層：感知 → 決策 → 執行

```
世界狀態 ──► 感知（我知道什麼）──► 決策（我要做什麼）──► Intent ──► Character
              視野/聽覺/記憶          FSM/BT/Utility        與玩家同一個入口
```

**執行層走 Character 的 intent 介面**（見 `system-3c.md`）：AI 不直接改位置、不直接播動畫——它跟玩家一樣「產生意圖」，由同一個 Character 執行。紅利：AI 自動遵守能力鎖與狀態機規則（暈眩中 AI 也出不了招，不用另寫）、AI/玩家行為可互換（錄製 AI 當教學示範、玩家托管）。

## 決策架構選型

| 架構 | 本質 | 適合 | 何時放棄 |
|------|------|------|---------|
| **FSM** | 狀態 + 轉移條件 | 行為 ≤ 5-6 態的雜兵（巡邏/追擊/攻擊/逃跑） | 轉移邊開始爆炸（每加一態要考慮 N 條邊）|
| **Behavior Tree** | 樹狀優先序 + 條件節點 | 中等複雜敵人與 boss：行為有清楚的優先層次 | 行為間需要連續權衡（不是「優先序」而是「哪個比較划算」）|
| **Utility AI** | 每個行為算分，選最高 | 多目標多選項的權衡（打誰、用哪招、撤不撤） | 分數公式難以調教、行為順序需要嚴格保證時 |
| **GOAP / 規劃器** | 從目標反推行動序列 | 開放環境的湧現行為（模擬向） | 動作遊戲幾乎用不到——可讀性差、除錯昂貴 |

**實務上是混搭，不是單選**：

- 雜兵：FSM 就好——別給 20 血的小怪上 BT，除錯成本不成比例。
- 精英/boss：**BT 當骨架**（受擊反應 > 保命 > 攻擊 > 索敵的優先層次），**Utility 當葉子**（「攻擊」節點內部用打分選具體招式與目標）。這是動作遊戲最常見的甜蜜點。
- 狀態機的畫法與轉移條件紀律見 `../../../diagram/game-diagrams/references/state-machine-diagram.md`（條件可判定、圖即 spec）。
- 行為參數（視野距離、攻擊冷卻、逃跑血量閾值）全部外化成資料（`data-config-driven.md`）——**同一棵樹 + 不同參數表 = 不同性格的敵人**，這是內容量產的槓桿。

## 感知：結果是資料，不是即時查詢

**問題**：決策層直接呼叫 `can_see_player()`，每個節點各查一次——貴、且同幀內結果可能不一致。

**解法**：感知層獨立 tick，產出**刺激記錄（stimulus）**，決策層只讀記錄：

```
struct Stimulus: type(visual|sound|damage), position, target_id, time, strength

感知 tick（降頻 5-10Hz，錯開相位——見 perf 的降頻）:
    視野：扇形角度 + 距離 + raycast 遮擋（見 algo-physics 的 raycast）
    聽覺：聲音事件廣播（腳步/槍聲帶半徑），距離內登記 stimulus
    受擊：傷害事件直接寫入（被打永遠知道方向）

記憶：last_known_position + 信心值隨時間衰減
     ——玩家躲起來後 AI 去「最後看到的位置」搜索，而不是瞬間失憶或全圖鎖定
```

- **感知不對稱是難度工具**：AI 的視野角、反應延遲（stimulus 到決策的延遲 0.2-0.5s 模擬人類反應）都是資料——難度調這些，比調血量攻擊高明（見下方「難度」節）。
- **別讓 AI 讀世界真值**：直接讀玩家座標的 AI 在玩家繞後時瞬間轉身——「全知」是體感作弊的頭號來源。

## 群體協調：攻擊權配額（token）

動作遊戲的經典問題：五隻怪同時撲上來，玩家只有被淹死一種結局。解法是**攻擊 token**：

```
squad_manager:
    attack_tokens = 2            # 同時最多 2 隻進攻
    enemy 想攻擊 → 申請 token：
        有 → 進攻；沒有 → 進入「威嚇位」（在包圍圈上游走、佯攻、吼叫）
    攻擊結束/死亡 → 歸還 token
```

- token 數就是**體感難度的主旋鈕**（資料化）；boss 戰的小怪、不同敵種可以有不同 token 成本（重型怪佔 2）。
- 威嚇位不是閒置——遊走與佯攻維持壓迫感，這是「看起來被圍毆、實際上可應對」的魔術（遭遇設計的意圖見 `../../../planning/game-design/references/level-encounter-design.md`）。
- 包圍站位：簡單做法是圍繞目標的固定槽位（slot）分配，避免全員擠同一點——槽位分配也歸 squad manager，個體只負責走到自己的槽。

## 移動執行：路徑是骨架，steering 是肌肉

- **Pathfinding**（`algo-search.md`）給全域路徑：去哪、怎麼繞過牆。
- **Steering**（`algo-physics.md`）管局部：沿路徑移動時的避障、與同伴的分離（separation）、到槽位的 arrive。
- 分工界線：路徑點是「建議」，steering 有權在局部偏離（避開突然出現的障礙）；偏離過遠才重新尋路（設閾值，別每幀重算——大量單位的尋路要排隊分幀，見 perf 的 time-slicing）。

## 表演性：可讀、會失誤、難度是行為

- **每個攻擊都有 telegraph**：前搖是給玩家的語言（見 `system-action-combat.md` 的時間軸與 `../../../workflow/game-production/references/art-visual-readability.md`）——AI 架構要保證「決策 → 前搖 → 生效」的順序不可跳過。
- **故意留破綻**：攻擊後的硬直窗口、輪流進攻的間隙——「AI 的失誤」是設計出來的獎勵時機，寫進行為資料。
- **難度 = 行為參數，不是數值膨脹**：反應延遲、攻擊頻率、token 數、連招長度、佯攻比例——這些做成難度參數表；血量攻擊翻倍是最懶的難度（海綿化警告見 encounter-design）。

## 除錯（AI 是黑箱之王，工具先行）

- 頭頂顯示當前狀態/行為節點、目標線（見 `../../../tools/game-tooling/references/debug-draw.md` 的 AI 層清單）。
- 感知可視化：視野扇形、聽覺半徑、last known position 標記。
- **決策 log**：每次行為切換記「從 X 到 Y，因為 <條件>」（`../../../tools/game-tooling/references/debug-logging.md` 的狀態轉換埋點）——BT 深了以後，沒有這條 log 等於不可維護。
- 控制台：凍結 AI、強制指定行為、單獨放行一隻（`../../../tools/game-tooling/references/debug-console-and-cheats.md`）。

## 常見陷阱

- **AI 繞過 intent 直接操作角色**：位置硬設、動畫硬播——能力鎖失效、與玩家行為規則分裂。執行層唯一入口是 intent。
- **每幀全量決策**：全場 AI 每幀跑 BT + 每幀感知 raycast——降頻 + 相位錯開 + 距離分級（遠處降到 1Hz 或休眠），見 perf 的降頻與 LOD 思維。
- **聰明但不可讀**：完美繞後、預判走位、零延遲反應——玩家讀不懂就只剩挫折。先問「玩家看得懂嗎」再問「AI 強不強」。
- **行為寫死在程式**：每種敵人一個 class 覆寫——參數化 + 資料表（同一棵樹養全家族），否則第 15 種敵人時量產卡死。
- **群體無協調**：沒有 token 的近戰群 = 疊在一起的絞肉機；有 token 沒威嚇位 = 排隊送死的喜劇。兩個都要。
