# Clean Code

> **定位**：語言中立的**可讀性 / 可維護性決策**——「何時抽函式、這名字表達了意圖嗎、這註解該存在嗎、這 smell 該重構嗎」。**不含**具體風格慣例（縮排、PascalCase/camelCase、大括號位置——那是個人硬規則，留你的 CLAUDE.md，各語言/團隊不同）。

**先查域總表，再進家族細表。**

## 域總表

| 你的問題 | 家族 | 細表 |
|----------|------|------|
| 名字取得好不好、怎麼表達意圖 | 命名 | ↓ Naming |
| 函式該多小、要不要抽、參數/副作用、巢狀太深 | 函式 | ↓ Function |
| 這段該加註解嗎、有沒有 code smell、要不要重構 | 壞味道 | ↓ Smell |

貫穿心法：**程式碼被讀的次數遠多於被寫**——所有取捨都偏向讀的人。可讀性不是「加註解」，是**讓程式碼本身不需要註解**（好名字 + 小函式 + 無 smell）。
