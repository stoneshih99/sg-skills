# 遊戲動畫原則

傳統動畫十二原則在遊戲裡要重新排序：**可中斷性與回應速度優先於流暢**。影視動畫觀眾只看；遊戲動畫玩家在等它讓出控制權。

## 十二原則的遊戲化取捨

最常用的幾條與其遊戲版變形：

- **預備（Anticipation）**：攻擊前搖給讀取與重量感——但幀數受手感預算約束（見 `../../game-design/references/feel-input-responsiveness.md` 的 100ms 反應預算）：玩家自己的動作前搖要短（重要的是回應感），**敵人的前搖要長**（那是給玩家的 telegraph，見 `art-visual-readability.md`）。同一條原則，兩個方向。
- **擠壓與伸展（Squash & Stretch）**：落地擠壓 1-3 幀、起跳伸展——廉價又有效的重量感來源，2D 3D 都適用（程式做縮放即可，不必進動畫資產）。
- **跟隨與重疊（Follow-through & Overlap）**：披風、頭髮、武器的延遲跟隨——用程式的次級動態（spring/verlet）做，比烘進動畫省資產又自然。
- **弧線（Arcs）**：揮擊軌跡走弧線——攻擊判定與特效軌跡（見 `anim-vfx-design.md`）要跟著動畫的弧走，三者分家就「假」。
- **誇張（Exaggeration）**：遊戲鏡頭遠、時間短，動作幅度要比寫實大 20-50% 才讀得到——「照動捕原樣用」是動作糊的常見原因。

## 前搖、生效、後搖：動畫即攻擊資料

戰鬥動畫的三段結構直接對應 gameplay 資料（見 `../../game-design/references/feel-input-responsiveness.md` 的取消窗口）：

```
[前搖 anticipation] → [生效幀 active] → [後搖 recovery]
   不可取消              判定/特效/音效        可被取消（窗口）
```

- **生效幀是三方同步點**：命中判定、hitstop、特效、音效同一幀（見 impact-feedback）——動畫做好後用逐幀工具標出生效幀，寫進資產 metadata（哪一幀出判定、哪一幀可取消），實作端照表接。
- **動畫服務手感的鐵律**：手感需要 6 幀前搖，動畫就是 6 幀——動畫師想要 12 幀的「完整感」時，砍的是玩家的操作感。時機由 gameplay 定，動畫在時機內做到最好。

## 狀態機與 Blending

- **動畫狀態機跟著邏輯狀態機走**（見 `../../game-diagrams/references/state-machine-diagram.md`）：一個邏輯狀態對應一個動畫狀態，別讓動畫層自己長出邏輯。
- **轉移時間逐條調**：idle→run 可以 0.2s 混合；任何→受擊要瞬切（混合會吃掉打擊感）；落地→idle 短混合。預設全部同一個混合時間是「動作黏糊」的主因。
- **分層（layering）**：上半身開槍 + 下半身跑步用骨架分層與遮罩——但層一多優先權就亂，超過 2-3 層先重新想需求。
- **循環與非循環分清楚**：位移類循環（首尾無縫，見 `art-asset-types.md`）；動作類一次性，結尾回 idle 的銜接姿勢要接得上。

## Root Motion vs 程式位移

- **程式位移**（動畫原地播、位移程式算）：手感可調、可預測、網路同步友善——**動作遊戲預設選這個**。
- **Root motion**（位移烘在動畫裡）：貼地自然、複雜位移（翻滾、攀爬）不滑步——代價是手感被動畫綁死、調參要回動畫資產。
- 常見混合：平時程式位移，特定動作（處決、攀爬、閃避）切 root motion。**全專案規則寫死**，混用無章法 = 滑步與穿模的溫床。

## 常見陷阱

- **動畫做完才接手感**：前搖太長、不能取消，返工重做——時機用灰盒佔位動畫先驗（見 SKILL.md 的「時機先於畫面」）。
- **轉移全用預設混合**：受擊、落地這些「事件感」動作被混合抹平。
- **待機動畫太搶戲**：大幅度呼吸與晃動讓角色「站不穩」，也干擾玩家讀敵人前搖。待機要安靜。
- **每個動作都做全新動畫**：變體用「基底動畫 + 上層疊加/替換部分骨架」組合，資產量減半（同 content-production 的模板化思維）。
