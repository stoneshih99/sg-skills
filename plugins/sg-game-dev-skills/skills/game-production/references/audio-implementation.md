# 音訊實作

音效檔做得再好，觸發亂寫一樣毀掉——重複轟炸、該響不響、發聲數爆炸。這篇是接引擎時的實作模式。

## 觸發規則：事件 → 音效的對照層

音效觸發做成**資料對照**，不要散落在各系統的程式裡（見 `../../game-architecture/references/data-config-driven.md`）：

```
# 音效事件表（資料，非程式）
event: enemy_hit
    sound: sfx_hit_flesh      # 指向音效資產（含變體組）
    bus: combat
    variants: 4               # 隨機不重複
    pitch_range: ±8%
    volume_range: ±2dB
    cooldown_ms: 30           # 同事件最小間隔
    max_concurrent: 3         # 同時最多幾個實例
```

- 遊戲程式只發事件（`play("enemy_hit")`），播放策略全在表裡——音訊設計師可以不動程式調行為。
- **佔位音第一天就走這條路**：白盒期就用事件表接佔位音，換正式資產只換檔案（見 `audio-sfx-design.md` 的佔位音陷阱）。

## 隨機化與防重複

- **pitch/volume 隨機**：每次播放在小範圍內隨機（音高 ±5-10%、音量 ±2-3dB）——一個檔案聽起來像好幾個。
- **變體輪替**：隨機但不連續重複（shuffle bag：全部播過一輪才重來）。
- **同事件節流（cooldown）**：機關槍式觸發（連擊、群體命中）設最小間隔，30-50ms 內的重複觸發合併或丟棄——否則音量疊加炸耳。

## 3D 音訊與距離

- **衰減曲線**：距離衰減用對數型（近處變化敏感、遠處平緩），每類聲音定最小/最大距離——最小距離內不再變大（貼臉不炸耳）、最大距離外直接不播（省 voice）。
- **2D/3D 分工**：UI、音樂、玩家自身動作用 2D（不隨鏡頭變化）；世界中的聲源用 3D。玩家自己的腳步聲做成 3D 會隨鏡頭亂飄——常見錯誤。
- **遮擋（可選）**：牆後的聲音悶化（低通濾波）——用簡單 raycast 判定（見 `../../game-architecture/references/algo-physics.md` 的 raycast）就有巨大沉浸感提升，不用完美聲學模擬。
- **提示音的方向性是 gameplay**：敵人腳步、遠處槍聲的方位資訊是競技/潛行遊戲的核心回饋——這類聲音的 3D 定位精度優先於好聽。

## 發聲數與效能

- **voice 上限**：同時發聲數設全域上限（行動 16-32、PC 32-64 量級，實測為準）與**每 bus 上限**——爆量時誰被砍要可控。
- **搶佔策略（voice stealing）**：超上限時砍「音量最小/最舊/優先級最低」的——優先級跟著 `audio-mixing-loudness.md` 的層級走：預警與玩家回饋永不被砍。
- **距離剔除在播放前**：超出最大距離的請求直接不建 voice，而不是建了聽不到（同 profiling 的「少做事」原則，見 `../../game-tooling/references/perf-optimization-playbook.md`）。
- **載入策略**：短音效常駐記憶體、長音樂串流——全部常駐爆記憶體、全部串流爆 IO。
- 音訊也有幀預算：voice 數與 DSP 處理（殘響、濾波）是 CPU 成本，profiler 看得到（見 measurement-first）。

## 除錯支援

配 `../../game-tooling/` 建音訊除錯工具：

- 螢幕面板顯示當前 voice 數 / 各 bus 電平（watch 面板）。
- 控制台指令：靜音單一 bus（`audio mute music`）、列出正在播放的音效——「這聲音是誰發的」是音訊除錯第一問。
- 3D 聲源的 debug draw：畫出發聲位置與衰減半徑。

## 常見陷阱

- **觸發寫死在程式**：每個音效一行 hardcode，音訊設計師每次調整都要找工程師。事件表第一天建。
- **沒有 cooldown**：20 隻怪同幀死亡 = 20 個死亡音疊加，音量瞬間爆表。
- **voice 無上限**：平常沒事，高峰場面音訊系統把 CPU 吃掉——上限與搶佔是保險絲，一開始就裝。
- **記憶體無預算**：音訊悄悄吃掉幾百 MB（未壓縮 wav 常駐）——壓縮格式與載入策略進規格表（同 `art-tech-specs.md` 的壓縮紀律）。
