# HUD 與選單

HUD 的問題幾乎都是「太多」，選單的問題幾乎都是「太深」。這篇給裁減與扁平化的方法。

## HUD 資訊分級

把想放上 HUD 的每項資訊按「玩家決策頻率」分三級：

| 級別 | 判準 | 顯示方式 | 例 |
|------|------|---------|---|
| 常駐 | 每幾秒就要看一次 | 固定位置、一眼可讀 | 血量、彈藥、準星 |
| 情境 | 特定狀態才需要 | 觸發時出現、事後淡出 | 互動提示、低血警告、任務更新 |
| 查閱 | 想知道才看 | 收進選單/長按顯示 | 詳細屬性、地圖全覽、任務清單 |

- **常駐位的預設答案是 no**：每個常駐元素都要回答「玩家每分鐘看它幾次？」——答不出頻率的，降級到情境或查閱。
- **情境顯示是 HUD 瘦身的主力**：血量滿時血條淡出、戰鬥外彈藥收起——「需要時才在」讓畫面平時乾淨，出現本身也成為訊號（同 `audio-music-interactivity.md` 的「音樂停=訊號」邏輯）。
- **世界內顯示（diegetic）優先考慮**：血量做在角色背上的燈、彈藥顯示在槍身——資訊進世界，HUD 就能再少一件。做不到再退回螢幕空間。
- **位置慣例**：血量左下/左上、小地圖角落、彈藥右下——玩家帶著慣例來，違反要有強理由。

## HUD 佈局

- **視線熱區**：畫面中央是遊戲的，UI 靠邊；**但反應攸關的資訊靠近準星/角色**（低血變色、技能就緒閃光放在視線焦點附近，而不是要求玩家掃角落）。
- **群組相關資訊**：血量/護盾/狀態效果聚一起，彈藥/技能聚一起——掃一眼一組，不是滿場找。
- **層級用尺寸與對比表達**（同 `art-visual-readability.md` 的視覺層級）：HUD 自己也有第一二三層，全部同尺寸同亮度 = 全部一樣不重要。

## 選單結構

- **深度 ≤ 3 層**：主選單 → 分類 → 項目。第四層開始玩家迷路——寬勝於深（一屏多分類 > 層層鑽入）。
- **高頻操作最短路徑**：統計玩家最常做的三件事（繼續遊戲、換裝備、調音量），各自的點擊/按鍵數壓到最少——「繼續遊戲」永遠是第一焦點。
- **進出對稱**：怎麼進來就怎麼出去（Esc/B 一路退到底），每一層都能一鍵返回——畫面流程圖上檢查（見 game-flow-diagram 的返回路徑）。
- **狀態保留**：離開選單再回來，停在上次的位置——每次都從頭捲動是慢性折磨。
- **確認框只給不可逆**：刪存檔要確認；退出選單不要——到處都是「你確定嗎？」，玩家就不再閱讀直接連按。

## 資訊呈現

- **數字 vs 圖形**：精確比較用數字（傷害 127→135），狀態感知用圖形（血條）——兩者都要時「圖形為主、數字為輔」小字並列。
- **變化要可見**：數值變了要有動態（血條掉的紅色殘影、金幣跳動）——靜態刷新玩家看不見（見 `ui-interaction-feel.md` 的回饋）。
- **文案精簡**：按鈕用動詞（「裝備」不是「確定」）、說明一句話內——長文案在遊戲裡沒人讀（教學不靠文字，見 `../../../planning/game-design/references/level-teaching-through-design.md`）。

## 常見陷阱

- **HUD 當儀表板做**：把所有系統數值都掛上去，畫面像飛機駕駛艙——回到決策頻率分級。
- **選單結構跟開發結構走**：按「系統模組」分頁（背包系統/強化系統/圖鑑系統），而不是按玩家任務分（「我要變強」的裝備+強化在兩個不同深處）——按玩家意圖組織。
- **PC 思維的手把選單**：滑鼠隨便點的網格，手把要按十次方向鍵——焦點導航設計見 `ui-interaction-feel.md`。
- **開發者盲測**：自己天天看的 HUD 永遠「很清楚」——玩測時問玩家「現在血量多少、錢多少」，答不出來就是 HUD 失職（玩測法見 `../../../planning/game-design/`）。
