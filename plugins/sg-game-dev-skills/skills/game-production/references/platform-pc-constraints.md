# PC 平台約束（PC Constraints）

PC 的約束不是效能天花板，是**碎片化與玩家期待**：任意硬體組合、三種輸入裝置隨時熱插拔、視窗與多螢幕、Steam 生態慣例。這篇管引擎中立的設計決策；引擎層落地見 **sg-unity-dev-skills** 的 build-platform。主機平台（TRC/XR/Lotcheck 認證）是另一個量級的合規清單，決定上主機時另行研究，本篇不展開。

## 輸入：三種裝置，隨時切換

- **鍵鼠 + 手把 + Steam Deck 都要活**：輸入抽象成動作而非按鍵（意圖分層見 `../../game-architecture/references/system-3c.md`）；**重綁鍵是 PC 玩家的基本期待**，不是進階功能（`ui-accessibility.md`）。
- **熱插拔與 runtime 切換**：手把按下第一顆鍵的瞬間，全部按鍵提示圖示跟著切成手把 glyph、滑鼠游標隱藏；回敲鍵盤再切回來。要不要支援混用（鍵盤移動＋手把瞄準）明確決策，別讓它「碰巧能動」。
- **手把 glyph 家族差異**：Xbox / PS / 任天堂的確認與取消位置相反——glyph 與按鍵名**資料化**，別把「按 A 確認」hardcode 進字串（與 `loc-text-externalization.md` 的字串外化同一紀律，翻譯和換手把都會炸）。

## 顯示碎片化

- **解析度與長寬比**：16:9 為主，但 21:9、16:10、4K 都真實存在——UI 錨定與安全框（`ui-tech-specs.md`）。**21:9 給不給更寬視野是設計決策**（PvP 是公平問題），上線前定，別讓玩家用拉伸畫面替你決定。
- **視窗三態**：全螢幕 / 無邊框 / 視窗——無邊框是現代預設（alt-tab 快、多螢幕友善）；記住玩家上次的模式、尺寸、位置。
- **高更新率螢幕普及**：144Hz+ 下「物理綁幀率」直接壞掉（遊戲跑 2.4 倍速）——邏輯 fixed timestep、渲染插值解耦，第一天就對。
- **多螢幕**：全螢幕遊玩時鎖定滑鼠，別讓瞄準甩出去點到第二螢幕的東西。

## 畫質選項：玩家期待自訂

- **畫質選單是 PC 的門面**：檔位（低/中/高）＋ 個別項覆寫；檔位資料驅動（`../../game-architecture/references/data-config-driven.md`），**與行動的發熱降級檔位是同一套系統**（見 `platform-mobile-constraints.md`）——設計一次，兩平台複用。
- **首次啟動偵測硬體給預設檔位**：別讓 4090 玩家在最低畫質開場，也別讓文書機開場就卡死。
- **改動要即時預覽或明標「需重啟」**：調了沒反應是退款理由。
- **min spec 是商業決策**：定了才有測試底線與商店頁承諾；**Steam Deck 當驗證機划算**——手把操作、小螢幕字級、固定效能預算，一台機器掃三類問題。

## Steam 生態與桌面慣例

- **平台功能選型**：成就（低成本高期待，首發就該有）、雲存檔（存檔路徑集中一處就近乎免費——與 **sg-unity-dev-skills** asset-save-persistence 的路徑集中原則同一件事）、Rich Presence（免費曝光）、Workshop/mod（大決策——`data-config-driven` 的可 mod 設計是前置，不是上線後補）。
- **存檔寫使用者資料目錄，不是安裝目錄**：更新與檔案驗證會清掉安裝目錄的野檔案。
- **桌面公民行為**：alt-tab 不崩、失焦不吃輸入；失焦暫停/靜音做成**選項**（單機預設開、掛機類要能關）；點視窗關閉 = 存檔＋乾淨退出，不是 process kill。

## 常見坑

- **按鍵提示 hardcode「Press E」**：手把玩家看不懂、翻譯炸——glyph 資料化。
- **物理綁幀率**：144Hz 螢幕上速度全錯——fixed timestep 是底線。
- **21:9 沒決策**：拉伸變形或黑邊，上線被截圖嘲諷。
- **存檔寫進安裝目錄**：更新即消失。
- **失焦繼續吃輸入、出聲音**：背景遊戲搶麥搶鍵，桌面公民失格。
- **只在開發機測**：min spec 機器從沒開過機，商店頁的最低配置是抄來的。
