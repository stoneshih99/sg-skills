# 美術資產來源選型（自繪 / 資產包 / 外包 / AI 生成）

一人工作室的美術第一題不是「怎麼畫」，是「**從哪來**」——四個管道各有成本結構與陷阱，而且幾乎一定是混搭。這篇管管道選型與 AI 生成的管線邊界；動畫的技術選型（逐幀 vs 骨骼）見 `anim-2d-frames-vs-skeletal.md`。

## 四管道對照

| 管道 | 成本結構 | 一致性 | 獨特性 | 主要風險 |
|------|---------|--------|--------|---------|
| **自繪** | 時間（技能門檻高） | 最高 | 最高 | 速度慢到拖垮專案 |
| **資產包**（store） | 錢少、即時 | 跨包混搭必飄 | 低（撞臉） | 授權範圍、風格鎖死 |
| **外包** | 錢多、有管理成本 | 靠規格與驗收撐 | 高 | 交接品質（見 `content-outsourcing-handoff.md`） |
| **AI 生成** | 錢少、迭代快 | **單張強、跨張弱** | 中 | 一致性、授權、平台揭露 |

**混搭是常態，換裝是紀律**：prototype 用資產包＋AI 白盒驗玩法，vertical slice 才定最終管道與風格（黃金樣本，見 `content-pipeline-setup.md`）——**prototype 資產要列「待換清單」**，沒列的那批一定會混進正式版。

## AI 生成的管線現實

AI 生圖的能力邊界決定它在管線裡的位置——**當概念與素材產生器，不當量產動畫機**：

| 做得好 | 做不好 |
|--------|--------|
| 概念探索（一晚 50 個角色方向） | **多幀一致性**——動畫逐幀生成必飄（線條、比例、細節每幀變） |
| 單張立繪、頭像、圖示、卡面 | 同角色多姿勢/多視角保持長相 |
| 貼圖、背景、宣傳圖 | 精確像素風（網格對不齊）、可編輯分層檔 |

- **動畫的正解是繞過弱點**：AI 生單張角色 → 人工拆件 → **骨骼動畫**（一張拆件圖驅動所有動作，完全避開逐幀一致性問題）——這是 AI 管線選骨骼而非逐幀的結構性理由（選型全文見 `anim-2d-frames-vs-skeletal.md`）。
- **一致性策略**（做不到完美，只能收斂）：角色參考圖鏈（每次生成都餵前一批定稿）、風格指南寫進 prompt 模板（`art-style-guide.md` 的文字版）、後製統一調色與描線。清稿工作量要進排程——AI 出的是 80% 底稿，不是成品。
- **授權與揭露是硬規則**：生成模型的商用條款要留存；**Steam 提交要求揭露 AI 生成內容**（提交表單必填項，隱瞞被抓是下架級——與 `platform-pc-constraints.md` 的平台規範同類）；行動雙商店也在跟進。發版檢查納入 `build-release-checklist.md`。

## 資產包的坑

- **授權範圍先讀**：單專案還是無限？可否改作？re-distribute 條款（打包進遊戲 OK、原檔進 git 公開 repo 常常不 OK）。
- **買前查來源檔**：有 PSD/Aseprite 分層檔才能改；只有攤平 PNG 的包，改風格等於重畫。
- **撞臉風險與對策**：熱門包玩家看過——至少換色、改剪影、混搭自製件。
- **跨包混搭必飄**：不同包的線寬、飽和度、透視角度不一致——選一個主包定調，其他管道向它對齊（黃金樣本原則）。

## 常見坑

- **prototype 資產無痛混進正式版**：沒有待換清單，上線前才發現風格三國志。
- **AI 逐幀生動畫**：每幀重生成，角色臉一幀一個樣——單張生成＋骨骼動。
- **AI 內容沒揭露就上架**：Steam 表單必填，隱瞞的代價遠大於揭露。
- **資產包授權沒查就進版控**：公開 repo 分發原檔違約。
- **四個管道各自為政**：沒有黃金樣本對齊，每個管道的產出都「自己看OK」、放在一起是拼貼畫。
