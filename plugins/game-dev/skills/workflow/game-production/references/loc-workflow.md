# 本地化流程

翻譯品質的上限由**交接品質**決定（與美術外包同一條定律，見 `content-outsourcing-handoff.md`）。譯者看不到遊戲——你給的 context 就是他的全部視野。

## 時機

- **架構決定（字串外化、RTL 與否、字型雙軌）**：第一天。
- **偽本地化測試**：alpha 起隨時可跑（見 `loc-layout-and-fonts.md`）。
- **正式翻譯**：**文字凍結（string freeze）之後**——beta 中後期。凍結前送翻，每次改文案都在燒翻譯費與一致性。
- **LQA（語言 QA）**：翻譯回填後、release 前（掛進 `build-release-checklist.md` 的回歸清單）。

## 翻譯交接包

比照美術規格包的思路，一次給足：

```
loc-handoff/
├── strings.csv/xliff     # 字串表：key、原文、context、字數上限（若有）
├── glossary.md           # 詞彙表：專有名詞的定譯（角色/地名/技能/系統詞）
├── style-guide.md        # 語言風格：語氣（正式/俏皮）、玩家稱呼、標點慣例
├── screenshots/          # 主要畫面截圖——context 欄的視覺補充
└── build-access          # 可玩 build + 全解鎖作弊（見 debug-toolkit）——譯者能進遊戲看，品質差一級
```

- **詞彙表是一致性的錨**：「Mana」全遊戲只有一種譯法——詞彙表先譯先審，再開放全文翻譯。系統詞（HP/buff/回合）優先收錄。
- **字數上限標在字串表**：UI 空間緊的 key 標最大字元數，譯者當場取捨，勝過 LQA 抓破版回修。
- **context 欄的品質檢驗**：譯者不問問題不代表 context 好——第一批交付的錯譯分佈就是 context 缺口地圖。

## LQA（Language QA）

翻譯回填不是結束，要在**遊戲裡**驗：

- [ ] **語境正確**：表格裡通順 ≠ 畫面上正確（按鈕上的動詞、性別指涉、上下文銜接）。
- [ ] **變數還原**：插值後的完整句子通順（`{n}` 帶入實際數字看）。
- [ ] **版面**：破版、截斷、字型缺字（偽本地化抓過一輪，這裡抓真實文本的殘餘）。
- [ ] **富文本標記**：顏色/粗體標籤配對完整（腳本可查，見 text-externalization 的標記規範）。
- [ ] LQA 由**母語者玩過**（至少主流程 + 全選單），不是譯者自己在表格裡複查。

## 文化化（Culturalization）

超出文字的在地考量——上架前掃一輪：

- **符號與圖像**：手勢、旗幟、宗教符號、歷史事件在目標市場的敏感性。
- **顏色慣例**：功能色的文化含義差異（紅色的吉凶兩義）——功能色系統（見 `art-visual-readability.md`）必要時 per-locale 覆寫。
- **分級與法規**：各市場年齡分級（血腥/賭博機制如轉蛋的申報）、平台的區域要求——這決定內容要不要做區域版本，越早知道越便宜。
- **命名檢查**：角色/技能名在目標語言有沒有不雅諧音——詞彙表審定時順手做。

## 更新與維護

- **增量翻譯流程**：版本更新的新字串 diff 出來送翻（key 穩定的另一個理由）——每次全表重送是燒錢。
- **翻譯記憶**：沿用同一批譯者/工具的翻譯記憶庫，一致性與成本雙贏。
- **社群回報通道**：上線後的錯譯回報格式（key + 截圖），修正走字串表熱更新（config-driven 的紅利）。

## 常見陷阱

- **沒凍結就送翻**：文案還在改就翻，同一句翻三次、版本對不上。
- **交接只給一張表**：沒詞彙表、沒截圖、沒 build——譯者只能瞎猜，LQA 變成重翻。
- **機翻直上**：機翻可當草稿，沒有母語者審校就上線，玩家一眼識破且評價反映在商店分數上。
- **把 LQA 當選配**：表格裡完美、遊戲裡災難是常態——沒進遊戲驗過的翻譯不算完成。
- **只翻遊戲忘了周邊**：商店頁、成就、系統權限彈窗、隱私政策（見 telemetry 的合規）——玩家的第一印象其實從商店頁開始。
