# 互動音樂

遊戲音樂與影視配樂的根本差異：**你不知道玩家會停留多久、什麼時候戰鬥**。互動音樂系統就是讓音樂跟著遊戲狀態走，而不是循環到玩家麻木。

## Loop 的基本紀律

- **無縫循環點**：尾巴的殘響要摺回開頭（不是硬切），驗收時連聽 3 次循環點。
- **循環長度 vs 停留時間**：玩家會在這區待 20 分鐘，90 秒的 loop 會被聽爛。對策不是寫更長，是**降低資訊密度**（探索音樂要「可忽略」）+ 互動變化。
- **強度要留頭寸**：探索 loop 就把鼓組拉滿，戰鬥時就沒得升了——平常跑 40-60% 強度，高潮才有空間。

## 垂直分層（Vertical Layering）

同一首曲子拆成可獨立開關的層，跟遊戲狀態掛鉤：

```
探索狀態： [pad 底層] ──────────────
接近危險： [pad 底層] + [節奏層]
戰鬥中：   [pad 底層] + [節奏層] + [主旋律/銅管層]
低血量：   上述 + [緊張弦樂層] 或 濾波處理
```

- 層與層**同 tempo 同調性**，開關用淡入淡出（1-4 小節）。
- 掛鉤的遊戲參數要少而明確：敵人距離、戰鬥狀態、血量——參數多了音樂變成隨機拼盤。
- 這是資料驅動的天然應用：狀態 → 層組合的對照表外化成設定（見 `../../../architecture/game-architecture/references/data-config-driven.md`）。

## 水平段落（Horizontal Re-sequencing）

曲子拆成段落（intro / loop A / loop B / 高潮 / outro），按遊戲事件跳轉：

- **轉場對齊節拍**：跳段落等到下一個小節/樂句邊界再切，比立即切自然得多——代價是延遲（一小節 @ 120bpm ≈ 2 秒），急事件（Boss 登場）用 stinger 蓋過去。
- **Stinger（一次性樂句）**：事件強調音（發現祕密、擊殺精英、任務完成）疊在音樂上播，不打斷主體——性價比最高的互動音樂手法，先做這個。
- 垂直 vs 水平選擇：狀態漸變（緊張度）用垂直；事件切換（進 Boss 房）用水平。多數遊戲兩者混用，小專案先垂直 + stinger 就夠。

## 靜默與留白

- **靜默是音樂的一部分**：全程有音樂 = 音樂失去意義。探索段落可以只留環境音，音樂在事件時進場——進場才有情緒重量。
- **音樂停 = 訊號**：戰鬥結束音樂收掉的那刻，玩家不看 UI 也知道安全了——這是資訊，跟 sfx 的職責一樣。
- 恐怖/緊張類型尤其靠留白：音樂一直在，嚇不到人。

## 實務清單

- [ ] 每個遊戲狀態（選單/探索/戰鬥/Boss/結算）都有明確的音樂行為定義（播什麼、怎麼進、怎麼出）。
- [ ] 狀態轉換矩陣：任兩狀態間的轉場方式寫清楚（淡出淡入？節拍對齊跳轉？stinger 橋接？）。
- [ ] 循環點驗收、長時間停留測試（掛機 20 分鐘聽會不會煩）。
- [ ] 音樂檔案的 loop 資訊（起訖 sample、tempo、調性）進資產規格表——實作端需要這些 metadata。

## 常見陷阱

- **音樂鋪滿全程**：從第一秒糊到最後一秒，高潮沒有對比。先設計「什麼時候沒有音樂」。
- **互動過度**：每個小事件都扯動音樂，聽起來像壞掉的點唱機。音樂反映「狀態」，sfx 反映「事件」——大事件才動音樂。
- **轉場硬切**：狀態一變立即切曲，節拍斷裂比不互動更糟。至少淡入淡出，最好節拍對齊。
- **寫了互動系統、音樂沒按規格寫**：垂直分層需要作曲時就分軌分層、水平跳轉需要段落等長對拍——系統與音樂要同一份規格（發包時規格包必含，見 `content-outsourcing-handoff.md`）。
