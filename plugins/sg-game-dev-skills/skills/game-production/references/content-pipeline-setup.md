# 從樣本到量產

量產管線的目標：讓「做第 30 關」和「做第 3 關」一樣順，且品質一致。管線建設的投資在量產第一週就回本。

## 黃金樣本先行

- **樣本 = 規格的實體**：文件寫「風格要統一」沒有用；一份能打開來對照的標竿內容才有用。樣本通常就是 vertical slice 的產物（見 `milestone-stage-definitions.md`）。
- **樣本要附「制作履歷」**：這份內容是怎麼做出來的——用了哪些工具、步驟順序、每步花多久。履歷就是管線的第一版文件。
- **從樣本擠出單位成本**：一關 / 一隻敵人 / 一件裝備的實測工時（見 `milestone-planning-and-estimation.md` 的估算分水嶺）——量產排程唯一可信的數字。

## 管線步驟固定化

把「從原始素材到進遊戲可玩」的路徑寫成固定步驟，每步明確輸入輸出：

```
例：一隻新敵人的管線
1. 設計表填列（數值、行為參數）→ 敵人資料表新增一列
2. 美術產出（模型/貼圖 per 規格表）→ 進 assets/enemies/<name>/
3. 匯入（自動設定 per 規範）→ 引擎資產
4. 組裝（prefab/藍圖 從模板複製改參）→ 可生成單位
5. 掛進遭遇表 → 關卡可用
6. 驗收清單過一遍 → 完成
```

要點：

- **內容即資料**：新內容 = 新增資料列 + 新資產，不是新程式（見 `../../game-architecture/references/data-config-driven.md`）。要寫程式才能加一件裝備，管線就還沒好。
- **匯入自動化**：資產進倉庫時的引擎設定（壓縮、格式、切片）用自動化規則套，不靠每個人手點——手點必然不一致。
- **模板化組裝**：新內容從「標準模板」複製起手（模板敵人、模板關卡），改參數而不是從零搭。
- **步驟間的檢查點自動化**：能寫驗證腳本就寫（貼圖尺寸、命名、缺欄位——見 `content-asset-conventions.md` 的規格表），人工只驗機器驗不了的（好不好看、好不好玩）。

## 批次思維

- **同工序批次做**：連做 5 關的白盒、再連做 5 關的美化，比一關做到底 × 5 快——工具切換與心智切換都有成本（與 data-oriented 的批次處理同一直覺）。
- **先全鋪白盒再打磨**：所有內容先到「可玩粗胚」，再統一拉品質——節奏與難度曲線要看全貌才調得動（見 `../../game-design/references/level-pacing-curve.md`），先打磨前三關的結果常是後面全部重調。
- **每週清點**：產出數 vs 計畫數、單位實際工時 vs 估算——單位成本悄悄上漲是量產期最重要的預警（超支處理見 milestone-planning 的爆炸砍法）。

## 品質飄移防治

量產中期的隱形殺手：越做越「順手」，第 20 關和第 3 關像兩個遊戲。

- **定期對照樣本**：每完成一批，把新內容與黃金樣本並排看。
- **飄移是雙向的**：品質下滑要拉回；品質「上漂」（越做越精）同樣是問題——前面的內容變相過時，且單位成本悄悄上升。想升級標準，正式改樣本、估算重算、舊內容排補課，而不是默默發生。

## 常見陷阱

- **沒有樣本就開跑**：規格全靠口頭與想像，第一批交付全數返工。
- **管線邊做邊發明**：每個人自己摸索步驟，同樣的坑每人踩一次。第一份內容的制作履歷就是管線文件的種子。
- **驗收全靠人眼**：機器能查的（命名、尺寸、缺檔）讓人查，查漏是必然，人力也耗不起。
- **量產期還在改工具**：管線大改應該發生在量產前；量產中改管線 = 一半內容是舊管線做的，一半是新的。
