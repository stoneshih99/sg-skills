# Pattern 選型與坑

**pattern 是詞彙不是目標**——「用了幾個 pattern」不是品質指標。這篇只收兩件 Claude 不會替你決定的事：**singleton 該換成什麼**、**狀態機該用哪種實作**；其餘 pattern 只給進場訊號（訊號沒出現就別上）。定義與 UML 不在此（已知）。

## Singleton：問題不是全域，是三件別的事

被罵的原因不是「只有一個實例」，是它同時帶來：

1. **隱藏依賴**：函式簽名看不出它用了什麼——呼叫 `Foo.Instance` 的程式碼，依賴圖是謊言。
2. **生命週期失控**：誰先初始化、誰先關閉沒人管——「A 的建構子抓 B.Instance，B 還沒好」是經典開場。
3. **測試無法替換**：靜態抓取無縫可插，想 mock 就得改全域狀態，測試互相污染。

**替代階梯（由好到壞，往下每一階多付一點債）**：

```
明確傳參          依賴出現在簽名上——能傳就傳，這是預設
> 建構子注入      組裝點集中，測試換替身
> 服務定位器      仍隱藏依賴，但至少可替換、生命週期集中
> singleton       無狀態工具類勉強可接受；有狀態的就是技術債
```

- **判準不是「幾個地方要用」，是「有沒有狀態」**：無狀態的工具（數學、格式化）做成靜態沒差；有狀態的（存檔、音訊、玩家資料）走上面三階。
- 幾十個系統互相依賴的組裝問題（模組生命週期、服務表、顯式初始化順序）是另一個量級——遊戲引擎脈絡見 **sg-game-dev-skills** 的 system-foundation，Unity 落地見 **sg-unity-dev-skills** 的 script-architecture-glue。

## 狀態機：三種實作，按規模選

| 實作 | 適用 | 崩點 |
|------|------|------|
| **enum + switch** | 狀態 ≤5、行為差異小 | 每加狀態要改所有 switch |
| **State 物件**（狀態=類，含 enter/exit） | 行為隨狀態大幅改變、進出有掛接/清理 | 類數量與樣板碼 |
| **轉移表**（資料驅動：狀態×事件→新狀態） | 轉移規則密集、要可設定/可視化 | 行為仍要掛回程式碼 |

- **enter/exit 是 State 物件的真價值**——資源掛接與清理有明確的家（與動畫狀態機的 OnEnter/OnExit 同構）。只有行為分支、沒有進出邏輯，enum+switch 就夠。
- **崩潰訊號是狀態組合爆炸**：狀態名開始出現「While」（`JumpWhileAttacking`、`JumpWhileAttackingStunned`）就是該分層（HSM）或換架構的信號。
- 遊戲 AI 的 FSM vs Behavior Tree vs Utility 是**另一個決策**（不是實作選擇，是架構選擇）——見 **sg-game-dev-skills** 的 system-game-ai。

## 其餘 pattern：進場訊號（沒出現就別上）

| Pattern | 進場訊號 | 訊號沒到時 |
|---------|---------|-----------|
| **Factory** | 同一段「條件→new 不同類」長到**第二處** | 直接 `new` |
| **Builder** | 參數多且有組合約束，`build()` 要驗不變式 | 具名參數 / 設定物件 |
| **Strategy** | 同一條決策軸的分支蔓延到**多處** | 一處 switch 沒有罪；有一等函式的語言傳 lambda 就夠 |
| **Decorator** | 功能組合爆炸（`BufferedEncryptedStream` 這種類名） | 直接寫死組合 |
| **Adapter** | 要隔離第三方，換庫時只改一處 | 直接用 |
| **Command** | 動作要 undo/回放/排隊/網路轉送 | 函式呼叫就是函式呼叫 |
| **Observer** | A 變化、B C D 要反應，且 A 不該認識它們 | 直接呼叫 |

**Observer 的兩筆債要先認**：①**訂閱洩漏**——訂了不退，物件死了 handler 還活著（紀律：訂閱綁 owner 生命週期，成對出現）；②**派發時機**——即時派發會重入（事件處理中又發事件），佇列派發延遲一幀但可控，**全系統選一種寫死**。

## 常見坑

- **為想像中的需求上 pattern**：一個實作的 strategy、一族產品的 abstract factory、只有一軸變化的 bridge——等第二個實例出現再抽（YAGNI / Rule of Three）。
- **singleton 網**：singleton 抓 singleton，初始化順序靠檔案載入運氣——替代階梯往上爬。
- **factory 回傳具體類**：呼叫端還是認識實作，白加一層。
- **FSM 硬撐組合爆炸**：狀態名有「While」就分層。
- **observer 鏈式雪崩**：事件處理發事件再觸發事件——重入保護或佇列派發，並給事件鏈除錯日誌。
- **用繼承做物件變體**：`EnemyFast`、`EnemyStrong`、`EnemyFastStrong` 類爆炸——變體是資料不是型別。
