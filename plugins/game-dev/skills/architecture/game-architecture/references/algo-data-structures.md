# 必備資料結構

選錯容器是遊戲效能問題最常見的根源。下面列出每種結構的操作複雜度、遊戲用途與陷阱。挑選時問三件事：**查詢 / 插入 / 刪除哪個最頻繁？要不要有序？是不是每幀執行？**

## Array / List（連續陣列）

- **複雜度**：索引存取 O(1)、尾端加入攤還 O(1)、中間插入 / 刪除 O(n)、查值 O(n)。
- **遊戲用途**：預設容器；快取友善，遍歷最快；物件池、元件陣列、逐幀處理的實體清單。
- **陷阱**：中間刪除搬移成本高——若不在意順序，用「與尾端交換再移除」（swap-and-pop）達成 O(1) 刪除；動態成長會重新配置，已知規模先預留容量。

```
function swap_remove(list, i):
    list[i] = list[last]      # 用尾端覆蓋
    list.remove_last()        # O(1)，但打亂順序
```

## Hash Map（雜湊表 / 字典）

- **複雜度**：平均插入 / 查詢 / 刪除 O(1)，最壞 O(n)。
- **遊戲用途**：id → 實體、資源快取、稀疏資料（哪些格子被佔用）、去重。
- **陷阱**：不保證順序；每幀對 hash map 大量迭代比陣列慢（快取不友善）；鍵若用浮點座標會有精度 / 碰撞問題，改量化成整數格。

## Stack（堆疊，LIFO）

- **複雜度**：push / pop O(1)。
- **遊戲用途**：UI 畫面 / 選單返回堆疊、undo、DFS 的顯式堆疊、狀態機的巢狀狀態。
- **陷阱**：只能存取頂端；需要中間存取代表選錯結構。

## Queue（佇列，FIFO）

- **複雜度**：enqueue / dequeue O(1)（用環形緩衝或雙端）。
- **遊戲用途**：事件 / 訊息佇列、BFS、生成波次、輸入緩衝。
- **陷阱**：用普通 array 從頭 dequeue 是 O(n)；用環形緩衝（ring buffer）或雙端佇列避免。

## Heap / 優先佇列（Priority Queue）

- **複雜度**：插入 O(log n)、取最小 / 最大 O(log n)、看頂端 O(1)。
- **遊戲用途**：A* / Dijkstra 的 open list、依時間排序的排程器（定時器 / 冷卻）、依威脅值選目標。
- **陷阱**：不支援高效「查任意元素」或「改任意優先度」——A* 常用「重複入列 + 出列時跳過過期項」或另接索引；別誤用成需要頻繁隨機存取的地方。

## Grid（均勻格）

- **複雜度**：座標 → 格 O(1)；範圍查詢 O(範圍內格數 + 其中物件數)。
- **遊戲用途**：tile 地圖、均勻空間分割做碰撞寬階段、影響力地圖、塔防 / RTS 佈局。
- **陷阱**：格子大小要貼近物件尺寸——太大每格塞太多物件失去剔除效果，太小則跨多格的物件要登記多次、記憶體浪費；世界很大而稀疏時改用 spatial hash。

## Spatial Hash（空間雜湊）

把連續座標量化成格座標，當 hash map 的鍵——等於「無限大又稀疏」的 grid。

- **複雜度**：插入 / 查詢平均 O(1)；鄰近查詢查周圍幾格。
- **遊戲用途**：開放世界 / 無邊界地圖的鄰近查詢與碰撞寬階段、boids / 粒子的鄰居搜尋。
- **陷阱**：格大小同樣關鍵；跨格物件需登記到覆蓋的所有格；每幀重建 vs 增量更新要權衡。

```
function cell_key(x, y, cellSize):
    return (floor(x / cellSize), floor(y / cellSize))

function nearby(pos, radius, cellSize, table):
    result = []
    for cell in cells_overlapping(pos, radius, cellSize):
        result.append_all(table[cell])
    return result       # 再做精確距離篩選
```

## Quadtree / Octree（四元樹 / 八元樹）

依密度遞迴把空間切成四 / 八份，物件多的地方切得細。

- **複雜度**：查詢 / 插入平均 O(log n)，退化時 O(n)。
- **遊戲用途**：**分佈不均**的 2D（quadtree）/ 3D（octree）場景之範圍查詢與碰撞剔除、視錐剔除、LOD。
- **陷阱**：物件頻繁移動時維護成本高（每幀重建或更新）；分佈均勻時 grid / spatial hash 更簡單更快；設定最大深度與每節點容量避免退化。

## Graph（圖）

節點 + 邊；用鄰接串列（稀疏）或鄰接矩陣（稠密）表示。

- **複雜度**：鄰接串列遍歷 O(V + E)、記憶體 O(V + E)；鄰接矩陣查邊 O(1)、記憶體 O(V²)。
- **遊戲用途**：pathfinding 的地圖圖、科技 / 技能樹、對話樹、狀態機、依賴關係。
- **陷阱**：稠密才用矩陣，一般遊戲地圖稀疏用鄰接串列；有環的圖遍歷要記 visited 防無限迴圈。

## 選型速查

| 需求 | 選這個 |
|------|--------|
| 順序遍歷 / 快取友善 | Array / List |
| key → value 快速查找 | Hash Map |
| 後進先出 / 返回堆疊 / undo | Stack |
| 先進先出 / 事件 / BFS | Queue |
| 每次取最小 / 最大（A*、排程） | Heap |
| 均勻密度的空間查詢 | Grid |
| 稀疏 / 無邊界的空間查詢 | Spatial Hash |
| 不均勻密度的空間查詢 | Quadtree / Octree |
| 節點與關係 / pathfinding 地圖 | Graph |

> 空間分割（grid / spatial hash / quadtree）是碰撞與範圍查詢的核心，和 `algo-physics.md` 的碰撞寬階段、`algo-search.md` 的地圖表示直接相關。
