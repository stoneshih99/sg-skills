# 視覺可讀性

玩家在 0.5 秒內要讀懂畫面：什麼是威脅、什麼能互動、該往哪走。可讀性壞掉的畫面，美術越精緻越糟——雜訊更貴了而已。這篇是驗收與診斷用的檢查法。

## 視覺層級（Visual Hierarchy）

畫面元素按 gameplay 重要性分配視覺權重，**不是**按美術心血分配：

1. **第一層（最搶眼）**：立即威脅（敵人攻擊預警、彈幕）、玩家角色。
2. **第二層**：可互動物（道具、機關、NPC）、目標指引。
3. **第三層（最收斂）**：背景、裝飾——再漂亮也不許跟前兩層搶。

分層的手段：**對比度**（前景高對比、背景低對比）、**飽和度**（重要的飽和、背景灰化）、**細節密度**（見 `art-style-guide.md`）、**光照**（重點打光）、**動態**（會動的天然搶眼——背景動畫是雙面刃）。

## 輪廓與識別

- **剪影測試**：全畫面轉純剪影，玩家角色、敵人類型、可互動物還分得出來才及格。角色設計期就做，不要等進場景。
- **敵我識別**：陣營用「形狀家族 + 色彩」雙編碼（見 `art-style-guide.md` 的形狀語言）——只靠顏色，色弱玩家與混戰場面都會失效。
- **同類同形**：同一種敵人/道具永遠同一個輪廓；換色皮（palette swap）表強度變體可以，但強度階序要一致（例如越紅越危險，全遊戲通用）。

## 色彩的功能分配

把調色盤的一部分**保留給功能**，美術不得挪用：

- **強調色專用**：例如「橘色 = 可互動」——那麼背景與裝飾就永遠不出現橘色。功能色被裝飾用掉的那天，玩家就開始亂點了。
- **警示色階**：危險預警（紅）、治療/增益（綠）之類的慣例色遵守直覺，別為了風格反著用。
- **色弱備援**：功能區分不能只靠紅綠——搭配形狀、圖示、明度差（快速自檢：截圖轉灰階，功能資訊還在嗎？）。

## 動態可讀性

靜態截圖可讀 ≠ 戰鬥中可讀：

- **攻擊預警（telegraph）最高優先**：敵人出手前的視覺訊號（變色、範圍圈、蓄力動畫）必須壓過所有特效——玩家死於沒看到的攻擊會罵不公平，死於看到沒躲掉的攻擊會怪自己（後者才是好的挫折，見 `../../../planning/game-design/` 的挫折觀察）。
- **特效分級**：與 game-feel 的回饋層對齊（見 `../../../planning/game-design/references/feel-impact-feedback.md` 的「回饋蓋過資訊」陷阱）——自己的特效再爽也不能遮住敵人的預警。
- **高峰場面測試**：最多敵人 + 最多特效的場景截圖與錄影驗收（就是 profiling 的重負載場景，見 `../../../tools/game-tooling/references/perf-measurement-first.md`——效能與可讀性用同一批場景驗）。

## 引導視線

關卡層面的可讀性（與 `../../../planning/game-design/references/level-teaching-through-design.md` 的引導視線同源）：

- 光、色彩對比、線條指向出口與目標；
- 可走區與不可走區的材質/明度差要穩定一致——玩家學一次就能全遊戲通用；
- 驗收法：找沒玩過的人看截圖 3 秒，問「你會往哪走？」。

## 驗收檢查清單

- [ ] 剪影測試：角色/敵人/互動物剪影可辨
- [ ] 灰階測試：功能資訊在灰階下仍在
- [ ] 3 秒測試：新眼睛看截圖能指出威脅與去向
- [ ] 高峰場面：最吵的戰鬥中預警仍清楚
- [ ] 功能色稽核：強調色沒有被裝飾挪用

## 常見陷阱

- **美術升級毀掉可讀性**：灰盒期很好玩，上美術後變難玩——背景細節搶了前景。層級規範要在美化前立好。
- **每個元素都想被看見**：特效組、UI 組、場景組各自加亮加動態，軍備競賽的結果是全部一樣吵。視覺權重是零和的，有人加就要有人減。
- **只在開發機大螢幕驗**：小螢幕/遠座距/高亮環境下再看一輪——目標裝置驗收同 profiling 原則。
- **可讀性當美術問題**：「看不清楚」常是設計問題（同屏太多種敵人、預警時間太短）——修法可能在企畫端（見 game-design-doc），不只是調對比。
