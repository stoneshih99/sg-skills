# 資產類型準則

各類資產的製作要點。通用規則（命名、位置、驗收）見 `content-asset-conventions.md`，這裡是每類的內容準則。

## Sprite / 2D 角色

- **原點與錨點統一**：角色腳底中心（或依遊戲慣例），全專案一致——原點亂跳，程式端每隻都要特調。
- **朝向慣例**：預設朝右（或朝左），翻轉由引擎做；不對稱設計（單肩武器）要決定翻轉策略（直接鏡像 or 兩套圖）。
- **尺寸以遊戲內像素為準**：先定「角色在畫面上占幾像素」，回推畫布大小；像素風格要定像素密度（PPU）且**全資產一致**，混密度的像素風一眼露餡。
- **留白最小化**：畫布緊貼內容（自動裁切），大量留白浪費圖集空間。
- **動畫幀規劃**：幀數預算按動作重要性分（攻擊 > 待機 > 位移）；關鍵姿勢優先，中間幀後補（見動畫段）。

## Tilemap / 地圖磚

- **磚尺寸第一天定死**：16/32/48 px（或 3D 的網格單位）決定一切後續——關卡尺度、角色比例、碰撞粒度（見 level-design 的尺寸網格）。
- **接縫規則**：邊緣像素的銜接規範（哪些磚必須無縫相連）；做一張「全磚種拼接測試圖」當驗收場景。
- **磚集組織**：地形磚（自動拼接規則）與裝飾磚分開；透視角度（純俯視 / 斜 45 / 側視）全磚集一致。
- **變化磚防重複感**：高頻磚（草地、地板）至少 3-4 個變體，隨機撒——大面積單磚重複是廉價感之王。

## UI 資產

- **九宮格（9-slice）優先**：面板、按鈕做成可拉伸的九宮格，而不是每種尺寸一張圖——規格標清楚切線位置。
- **狀態一次做齊**：按鈕的 normal / hover / pressed / disabled 四態同批交付，事後補做必色偏。
- **文字不進圖**：圖內嵌字 = 每個語言一張圖（本地化災難）。圖是圖，字用字型渲染。
- **安全區與最小尺寸**：可點擊元素的最小實體尺寸（行動裝置常見 44pt 級）、不同解析度的錨定規則進規格。
- **圖示語意一致**：同一動作永遠同一個圖示；圖示風格（線性/面性、圓角半徑、線寬）出一頁對照板。

## 動畫資產

- **關鍵姿勢優先（pose-to-pose）**：先交關鍵姿勢審方向，通過再補中間——方向錯的流暢動畫是全損（同 `content-outsourcing-handoff.md` 的草稿輪原則）。
- **預備與跟隨**：攻擊要有前搖（anticipation）與收尾（follow-through）——但幀數受手感預算約束：**動畫服務手感**，前搖幀數與取消窗口跟著 `../../../planning/game-design/references/feel-input-responsiveness.md` 走，不是反過來。
- **循環點乾淨**：跑步/待機等循環動畫首尾幀必須無縫，驗收時連播 10 次看。
- **根位移策略統一**：位移在動畫內（root motion）還是程式控制？全專案一致，混用是滑步 bug 之源。

## 3D 模型

- **比例與單位**：1 單位 = 1 公尺（或專案定值），所有 DCC 工具匯出設定統一；進引擎第一件事放到標準人形旁邊比對。
- **原點與朝向**：腳底原點、+Z（或引擎慣例）朝前——放錯原點的模型每次擺放都在付稅。
- **硬邊與法線**：平滑組/硬邊規則、法線烘焙的 cage 設定進規格——法線接縫是驗收常客。
- **UV 準則**：接縫藏視覺死角、texel density 達標（見 `art-tech-specs.md`）、鏡像 UV 的使用規則（省空間 vs 對稱穿幫的取捨）。
- **碰撞體另做**：渲染模型不當碰撞體，簡化碰撞網格（或原始形狀）另附（見 profiling 的物理熱點）。

## 常見陷阱

- **各類資產各自為政**：sprite 的 PPU、tile 尺寸、UI 基準解析度沒對齊，組畫面時互相不搭。開工前一張「尺度總表」全對齊。
- **只做理想狀態**：UI 沒做 disabled 態、角色沒做受擊閃白用的材質參數——實裝時才發現缺件（清單見 game-feel 的回饋層）。
- **忽略極端內容**：最長的名字撐爆 UI、最大的怪穿出畫面——每類資產用極端案例驗收。
