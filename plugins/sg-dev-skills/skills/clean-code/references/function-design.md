# 函式設計

函式是讀程式碼的最小單位。這篇是「該多小、要不要抽、參數怎麼收、副作用怎麼管」的決策——不是行數硬規則。

## 該多小：一個抽象層級做一件事

函式該小，但「小」不是數行數，是**單一抽象層級**：一個函式要嘛是決策/協調（呼叫別的函式），要嘛是細節（實際運算），別在同一個函式裡混。

```
# 壞：協調與細節混在一起
def checkout(cart):
    total = 0
    for item in cart:              # 細節：算總額
        total += item.price * item.qty
    if total > 100: total *= 0.9   # 細節：折扣規則
    charge(total)                  # 協調

# 好：每層一個抽象
def checkout(cart):
    total = apply_discount(subtotal(cart))
    charge(total)
```

判準：**能不能用一句話說出這函式做什麼、且不含「而且/然後」**。要用到「而且」通常代表可以拆。

## 抽取 vs 內聯（雙向決策）

抽函式不是越多越好——抽錯了製造「只被呼叫一次、名字很爛、要跳來跳去讀」的碎片。

**該抽取**：
- 重複出現（DRY）——但小心「看起來像其實語意不同」的巧合重複，抽了之後兩邊需求分岔會更痛（見 [comments-and-smells.md](comments-and-smells.md) 的 DRY 陷阱）。
- 一段程式需要一句註解解釋「這在幹嘛」——把註解變函式名，程式碼自己說話。
- 巢狀太深、一個函式做多個抽象層級。

**該內聯 / 別抽**：
- 抽出來只被呼叫一次、又沒讓呼叫端更好讀——只是把邏輯藏到別處，增加跳轉成本。
- 為了「函式要短」硬切成 `partA()`/`partB()` 這種沿行數切、不沿語意切的碎片。

**判準**：抽取要讓**呼叫端**更好讀（讀者看到名字就懂、不需要跳進去）。若呼叫端沒變好，別抽。

## 參數：越少越好

- **0-2 個理想，3 個要停一下，4+ 個幾乎都該重構**：包成物件，或代表函式做太多事。
- **布林參數是警訊**：`render(true)` 呼叫端看不懂；`render(true)` 常代表函式其實有兩個行為——拆成 `renderVisible()` / `renderHidden()`，或用具名參數/列舉。
- **別用 out 參數/旗標改變行為**：`process(data, validate=True)` 內部分岔，讀者要看實作才懂——拆函式。

## 副作用：講清楚，別偷藏

**函式名承諾什麼就只做什麼**。`getUser()` 卻順手初始化 session 是偷藏副作用——呼叫端不知道、測試難、順序耦合。

- **查詢與命令分離（CQS）**：函式要嘛回傳值不改狀態（查詢），要嘛改狀態不回傳（命令）——別又改又回傳讓人猜。
- 純函式（同輸入同輸出、無副作用）最好測、最好讀；把副作用推到邊界（I/O 層），核心邏輯保持純。

## Guard clause 取代巢狀

深巢狀 if 是可讀性殺手。**提早 return 處理例外/邊界**，讓主邏輯留在最淺層、不被縮排推走：

```
# 壞：箭頭形巢狀
def pay(order):
    if order:
        if order.valid:
            if order.balance > 0:
                ... # 主邏輯埋在三層裡

# 好：guard clause 先擋掉，主邏輯攤平
def pay(order):
    if not order: return
    if not order.valid: raise InvalidOrder
    if order.balance <= 0: return
    ...  # 主邏輯在最淺層
```

## 錯誤處理是一件事

- **錯誤處理不該淹沒主邏輯**：try 區塊裡只放「可能失敗的那一件事」，把主流程抽成函式，try/catch 保持薄。
- **回傳 null 是製造呼叫端的地雷**：能拋例外或回傳空集合/Optional 就別回 null，逼呼叫端到處 null check（漏一個就 NPE）。
- 別吞例外（空 catch）——要嘛處理、要嘛往上拋帶脈絡。

## 常見坑

- **一個函式多個抽象層級**：協調混細節——一句話說不清就拆。
- **為短而短**：沿行數切成 `partA/partB`——沿語意切，不沿行數。
- **抽了沒讓呼叫端更好讀**：只是搬家增加跳轉——內聯回去。
- **4+ 參數 / 布林旗標參數**：函式做太多——包物件或拆函式。
- **偷藏副作用**：名字沒承諾的事偷做——CQS，查詢命令分離。
- **箭頭形深巢狀**：主邏輯被縮排推走——guard clause 提早 return。
- **回傳 null**：呼叫端遍地 null check——空集合/Optional/例外。
