# 玩法機制設計（Mechanics Design）

機制是「規則 × 玩家行為」的最小單位。這篇管兩件事：**單一機制怎麼設計得有趣**、**多個機制怎麼組合不打架**。核心循環（機制串成的迴圈）見 `gdd-core-loop-design.md`——機制是零件，循環是引擎。

## 機制解剖：五個組件

拆任何機制都是這五件，設計新機制就是回答這五題：

```
動詞      玩家做什麼           跳、格擋、討價還價
資源      操作與消耗什麼       體力、彈藥、時間、資訊
規則      什麼可以什麼不行     格擋有前搖、彈藥有限
回饋      結果怎麼被感知       見 feel-* 三篇（手感是機制的一半）
目標      為什麼要做           傷害、通行、獲得資訊
```

診斷用法：機制「不好玩」時逐項查——常見是**資源沒有張力**（無限資源的動詞沒有決策）或**回饋斷裂**（做了但感受不到，那是 feel 層的活）。

## 有趣決策的四個條件

機制的樂趣核心是決策。一個決策有趣，需要同時滿足：

1. **有取捨**：沒有恆定最優解——「永遠選 A」的選擇不是決策是儀式。取捨的來源：資源競爭（回血還是輸出）、風險對報酬（貪刀還是撤）、短期對長期。
2. **有資訊**：玩家能推理，不是擲骰——看得到敵人抬手才有「該不該閃」的決策（資訊設計連到 `../../game-production/references/art-visual-readability.md` 的 telegraph）。
3. **有後果**：選了會影響後續狀態——無後果的選擇玩家會停止思考。
4. **頻率適當**：**決策密度**是節奏的內核——動作遊戲每秒微決策（走位）疊分鐘級決策（資源）；密度過低無聊、過高疲勞（節奏見 `level-pacing-curve.md`）。

## 深度 vs 複雜度：最重要的一組區分

- **複雜度** = 學習成本（規則數、例外數、介面元素數）。
- **深度** = 精通空間（有意義的狀態變化數、策略層次）。
- 目標永遠是**高深度低複雜度**（易學難精）：圍棋規則十分鐘、深度一輩子。
- **加規則是加複雜度，不一定加深度**——新規則若不跟既有規則產生新決策，是純負債。設計審查的第一問：「這條規則跟誰互動？」

## 機制組合：正交與湧現

- **正交機制相乘**：各自獨立的維度（移動 × 射擊 × 時間控制）組合出的狀態空間是相乘的——湧現玩法（設計者沒排練過的解法）從這裡來。
- **組合檢驗**：兩個機制同時使用時，有沒有產生**單獨使用時不存在的決策**？有 = 正交且相容；沒有 = 其中一個是裝飾；互相抵消 = 打架，砍一個。
- **核心機制優先**：一個核心動詞先打磨到「單獨玩就有趣」（灰盒裡跑半小時不膩），再加輔助機制——輔助機制的職責是**給核心動詞製造新情境**，不是提供替代玩法。搶戲的輔助機制是縫合怪的開端（見 `gdd-ideation.md`）。
- **機制預算**：小專案 1 個核心動詞 + 2-3 個輔助維度就夠深——內容量產靠「同機制 × 新情境」（見 `level-encounter-design.md` 的變奏），不靠新機制。

## 驗證：機制的最短路徑

- **紙上原型**：回合制、數值類機制用紙筆/桌遊化先跑——一小時驗證一個迭代。
- **灰盒原型**：即時類機制的最小可玩（方塊人 + 核心動詞），見 risk-assessment 的樂趣驗證——**驗證期禁止加美術**（分不清是機制有趣還是包裝討喜）。
- 迭代單位是「一條規則」：一次改一條，跟手感調參同一紀律（`feel-impact-feedback.md` 的一次調一項）。

## 常見陷阱

- **機制堆疊代替深度**：不好玩就再加一個系統——複雜度上升、深度原地踏步。先回頭修核心決策的取捨。
- **例外補丁**：平衡問題用特例規則修（「這招對 boss 無效」）——每個例外都是複雜度負債與玩家的信任損耗；平衡問題優先用數值解（`gdd-numeric-design.md`），數值解不了才動規則。
- **動詞過多**：八個按鍵八個動詞，每個都淺——砍到玩家會反覆用、用出花樣的那兩三個。
- **為差異而差異**：機制怪但不服務核心幻想——差異鉤子要長在樂趣上，不是長在「沒人這樣做過」上（沒人做過常常有原因）。
- **跳過單獨驗證直接組合**：核心動詞沒驗證就搭系統——地基不好玩，上面蓋什麼都白費（milestone 的 prototype 關卡就是在擋這個）。
