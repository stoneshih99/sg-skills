# 移動手感

「飄」與「笨重」是同一組參數的兩個極端：加減速太慢是飄，太快是生硬。移動手感的核心是**曲線**，不是速度值。

## 地面移動

- [ ] **加速 / 減速分開調**：起步加速時間與鬆手減速時間是兩個獨立參數。多數「跟手」的遊戲：起步 快（0.1-0.2 秒到全速），停下 更快（幾幀內停死或帶一點滑步）。
- [ ] **轉向加成**：反方向輸入時給額外加速度（或直接反轉速度），讓折返「聽話」。沒有轉向加成的角色會「滑一段才回頭」= 飄。
- [ ] **速度有層次**：走 / 跑 / 衝刺的速度差要一眼可辨（差 30% 以上），否則層次沒有意義。
- [ ] **地形差異**（若有）：冰面 / 泥地改的是加減速曲線，不是最高速——玩家感受曲線遠多於感受極速。

```
# 常用：不對稱的加減速
if has_input:
    speed = approach(speed, max_speed * input, ACCEL * dt)
else:
    speed = approach(speed, 0, DECEL * dt)      # DECEL 通常 > ACCEL
if sign(input) != sign(speed):                   # 折返
    speed = approach(speed, max_speed * input, TURN_ACCEL * dt)  # 最大
```

## 跳躍

- [ ] **上升快、下落更快**：下落重力 1.5-2.5 倍於上升重力。對稱拋物線是「月球感」的主因。
- [ ] **可變跳高**：長按跳高、早鬆手截斷上升（把上升速度砍半或加大重力）。給玩家精準控制。
- [ ] **頂點懸浮（apex hang）**：拋物線頂點附近略減重力幾幀，玩家有時間調整落點，跳躍「輕盈」的祕密。
- [ ] **終端速度**：下落速度設上限，超快的下落讓玩家無法反應且落地生硬。
- [ ] **空中控制**：空中的水平加速度通常低於地面（30-70%），但不能為零——完全不能空調的跳躍在現代手感裡幾乎不可接受。
- [ ] **落地回饋**：落地音效、小粒子、1-2 幀的擠壓（squash）。高處落地量級加大。
- [ ] 輸入容錯（coyote time、jump buffer）見 `feel-input-responsiveness.md`。

## 攝影機

攝影機是移動手感的隱形一半，角色調不好時常常其實是攝影機的鍋：

- [ ] **跟隨有阻尼**：攝影機平滑趨近目標而非硬鎖，但延遲要小（否則暈）。快速移動時可加大跟隨速度。
- [ ] **前視偏移（look-ahead）**：攝影機偏向移動 / 瞄準方向，把畫面空間留給「將要去的地方」。
- [ ] **死區（dead zone）**：小幅移動不動攝影機，避免鏡頭神經質。
- [ ] **垂直跟隨保守**：平台遊戲跳躍時鏡頭別跟著上下彈，通常鎖 Y 或只在落地後跟上。
- [ ] **框架事件**：衝刺 / 受擊 / 重落地時的 FOV 微調或短震（量級克制，見 `feel-impact-feedback.md`）。

## 排查法

1. 「飄」：先查鬆手減速與轉向加成（多半太弱），再查空中控制是否過強。
2. 「笨重」：查起步加速（太慢）、動作後搖（見 `feel-input-responsiveness.md`）、攝影機延遲（太大）。
3. 「月球感」：下落重力不夠、頂點懸浮過長、終端速度太低。
4. 調參時關掉動畫混合等干擾，用純膠囊體 + 除錯曲線圖（速度-時間）調，調完再接動畫。

## 常見陷阱

- **用真實物理當手感**：真實的慣性與拋物線幾乎必然難操控。手感是設計出來的假物理，真實只是參考。
- **只調最高速度**：玩家抱怨「太慢」時，加速度不足的機率大於極速不足。
- **動畫拖累移動**：移動參數遷就動畫長度（起步動畫播完才到速）——反了，動畫用混合去追移動。
- **每個角色 / 狀態手感不一致**：變身 / 載具 / 水下各自為政，基礎容錯（coyote、buffer）應全域一致。
