# 混音與響度

「聲音糊成一團」「音量忽大忽小」都是混音結構的病。混音骨架（bus、優先級、響度標準）要在音效大量進庫**之前**立好——事後重混幾百個音效比重做還痛。

## Bus 結構

所有聲音掛進分組匯流排（bus），控制以組為單位：

```
Master
├── Music
├── SFX
│   ├── Player（玩家動作）
│   ├── Combat（命中/爆炸）
│   ├── World（環境互動、腳步）
│   └── Ambience（環境底噪）
├── UI
└── Voice（若有語音）
```

- **玩家設定直接對應 bus**：音樂/音效/語音的音量滑桿就是 bus 音量——結構不對，設定選單做不出來。
- **處理掛在 bus 上**：壓縮、EQ、殘響掛組不掛單音——單音只管自己的響度與內容。
- 命名與掛法進資產規格表（每個音效登記時就指定 bus，見 `audio-sfx-design.md` 的清單欄位）。

## 響度標準

- **定內部響度基準**：同類音效目標響度一致（例如 UI 音 -23 LUFS、命中音 -18 LUFS 之類的內部標準——數字自訂，**一致性才是重點**），入庫驗收時量（可自動化，見 `content-asset-conventions.md` 的腳本化驗收）。
- **peak 留 headroom**：單檔 peak 不頂 0dB（常見 -3 到 -6dB），疊加與處理才有空間。
- **全遊戲輸出響度**：整體響度對齊平台慣例（主機平台有規範，行動裝置注意小喇叭），發佈前用實際裝置聽（同 `art-visual-readability.md` 的目標裝置原則）。

## 優先級與 Ducking

聲音同時發生時，誰讓誰——事先定規則，不靠運氣：

- **資訊 > 氣氛**：預警音、玩家受擊 > 環境音、音樂——與視覺層級同一邏輯（見 visual-readability 的層級表）。
- **Ducking（閃避）**：高優先聲音出現時自動壓低其他 bus——對話出現壓音樂（-6 到 -12dB，恢復要慢）、大爆炸瞬間壓環境。規則掛在 bus 之間，兩三條就夠，多了互相打架。
- **HDR 混音思維**：整體音量空間有限，想讓大爆炸「大聲」，不是推爆炸，是壓其他的——對比才是音量感的來源。

## 頻譜分配

糊成一團的常見原因：所有聲音都擠在中頻。

- **給每類聲音留頻段**：低頻給爆炸/重擊/音樂 bass、中頻給對話/主要回饋、高頻給 UI/細節——同頻段的東西同時響就互相遮蔽（masking）。
- **音樂給 sfx 讓位**：戰鬥音樂的編曲避開命中音的主頻段；做不到就用 EQ ducking（戰鬥中音樂中頻微降）。
- 快速診斷：頻譜儀看最吵的場景，哪段頻率堆成山，就是誰在打架。

## 驗收檢查清單

- [ ] bus 結構圖存在，每個音效都有指定的 bus
- [ ] 同類音效響度一致（腳本量測）
- [ ] 音量設定滑桿各自有效（音樂關掉音效還在）
- [ ] 最吵場景（同 profiling 的重負載場景）聽得清預警與玩家回饋
- [ ] 目標裝置實聽（手機小喇叭 / 電視 / 耳機各過一輪）

## 常見陷阱

- **每個音各自調到「夠大聲」**：軍備競賽的結果是全部貼頂、動態歸零——响度基準 + 對比思維。
- **混音等最後**：幾百個音效入庫後才發現響度亂跳，重量測重調一輪。基準第一天立，入庫時把關。
- **只用好耳機混**：玩家用手機喇叭與電視——爛喇叭聽不到你的 sub 低頻層（見 `audio-sfx-design.md` 的分層），重要資訊不能只放在低頻。
- **ducking 規則太多**：五六條規則互相觸發，音量像坐雲霄飛車。兩三條、恢復慢、閾值高。
