# Config 驅動設計

把遊戲的數值、平衡、內容從程式碼裡抽出來，變成外部**資料**（設定表 / 資產）。程式碼只寫「規則怎麼跑」，資料決定「跑成什麼樣」。設計師不改 code 就能調整遊戲，內容也能被 mod。

## 原則

- **數值外化**：傷害、冷卻、掉落率、關卡配置…不寫死在程式，放進表 / 資產。
- **程式是直譯器**：程式碼讀資料、依資料行動，本身不含具體數值。
- **內容即資料**：新武器 = 新增一列資料，而非新增一個 class。

```
# 寫死（難調、要重編譯）
function fireball_damage(level): return 10 + level * 5

# Config 驅動（設計師改表即可）
skills = load_table("skills.csv")
function skill_damage(skillId, level):
    row = skills[skillId]
    return row.baseDamage + level * row.damagePerLevel
```

## 資料形式

- **表格（CSV / TSV / 試算表匯出）**：大量同型列（技能表、道具表、敵人表）。設計師最順手。
- **結構化檔（JSON / YAML / 自訂）**：有巢狀 / 變長結構的設定（關卡、對話樹、行為配置）。
- **引擎資產（可序列化物件 / ScriptableObject 類）**：能在編輯器裡編、有型別檢查、可參照其他資產。

> 選擇：同型大量列 → 表格；巢狀 / 少量複雜設定 → 結構化檔或資產。

## Schema 與載入

- **定義 schema**：每個表 / 檔的欄位、型別、必填、預設值先講清楚，載入時據此驗證。
- **載入即驗證**：開場（或熱重載時）解析成記憶體中的純資料結構，並檢查——缺欄位、型別錯、參照到不存在的 id，要在載入期就報錯，別等執行到才炸。
- **用 id 互相參照**：武器表指向掉落表用 id；載入後可解析成索引以加速。

```
function load_and_validate(path, schema):
    rows = parse(path)
    for row in rows:
        for field in schema.fields:
            assert field.name in row, "缺欄位: " + field.name
            assert type_ok(row[field.name], field.type), "型別錯: " + field.name
        assert row.id not in seen, "id 重複: " + row.id
    return index_by_id(rows)
```

## 熱重載（Hot Reload）

把資料載入設計成可重新載入：改了表不用重開遊戲就看到效果，大幅加快設計師的調參迭代。前提是資料與行為分離乾淨——重載的只是資料，系統不需重啟。

## 遊戲情境

- 平衡調參：戰鬥數值、經濟曲線、掉落率反覆微調。
- 內容擴充：新道具 / 技能 / 敵人 = 加資料列。
- 可 mod / UGC：玩家用同一套資料格式擴充內容。
- 多語系 / 地區差異：文字與設定按資料切換。

## 陷阱

- **邏輯洩漏進資料**：把整段程式行為塞進設定（例如在表裡寫公式字串、迷你腳本）會變成難維護的自製語言；資料描述「參數與選項」，複雜行為留在程式，用資料選擇 / 組合它們。
- **沒有驗證**：資料錯（打錯 id、缺欄位）若拖到執行期才爆，很難追；一律載入期驗證並給清楚錯誤訊息。
- **過度外化**：把根本不會調的常數也做成表，只是徒增複雜度與載入負擔；只外化「會變、需要調、需要擴充」的東西。
- **表與程式假設脫節**：欄位語意只存在某人腦中；schema 與欄位說明要跟資料一起維護。
- **參照完整性**：跨表 id 參照要在載入時檢查存在，避免懸空參照。
