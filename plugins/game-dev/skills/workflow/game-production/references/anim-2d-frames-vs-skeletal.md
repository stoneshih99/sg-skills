# 2D 角色動畫選型：逐幀 Spritesheet vs 骨骼（Spine 類）

2D 角色動畫只有兩條技術路線：**逐幀**（每幀一張畫出來的圖，攤進 spritesheet）與**骨骼**（角色拆件＋骨架，動畫是骨架變換的插值——Spine / DragonBones / 引擎內建 2D 骨骼都是這路）。選錯的代價在**第 10 個動作**才爆發，所以這是立項決策。動作設計本身（前搖後搖、狀態機）見 `anim-game-principles.md`；Unity 落地見 **sg-unity-dev-skills** 的 unity-runtime anim 家族。

## 對照表：成本結構完全相反

| 維度 | 逐幀 Spritesheet | 骨骼（Spine 類） |
|------|-----------------|-----------------|
| **成本曲線** | 線性：動作數 × 幀數 × 朝向，每個新動作全額付費 | 前期 rig 貴（拆件＋綁骨），**每個新動作邊際成本低** |
| **視覺風格** | 手繪張力、形變自由（擠壓拉伸、剪影誇張）、像素風唯一解 | 平滑流暢，但易有「紙娃娃感」（部件剛性滑動） |
| **記憶體** | 圖集隨動作數膨脹（大角色×多動作是記憶體大戶） | 一張拆件圖打天下 |
| **執行期** | 換圖零計算 | 每幀算骨架（角色多時是 CPU 項目） |
| **換裝/換色** | 全部重畫 | 換件即可（換裝系統近乎免費） |
| **動作混合** | 不可能（只能硬切） | blend、IK、部分身體疊加（跑步中揮手） |
| **修改成本** | 改設計=重畫全部幀 | 改件圖，動作全部沿用 |

## 決策規則

- **動作數多、要換裝、角色大而少**（ARPG 主角、換裝養成）→ **骨骼**。
- **像素風、動作少而精、要爆發形變**（格鬥的誇張中間幀、平台跳躍的擠壓拉伸）→ **逐幀**。
- **AI 生成管線 → 骨骼**：單張生成＋拆件避開逐幀一致性弱點（理由見 `art-asset-sourcing.md`）。
- **混搭是常態且該定成規矩**：主角色骨骼、特效與小物件逐幀 flipbook（`anim-vfx-tech-specs.md`）——邊界寫進風格指南，別讓每個資產各自即興。

## 朝向數：藏在動畫背後的成本乘數

- 總成本 = 動作數 × 幀數 × **朝向數**——側視 2 向（翻面免費）最便宜；top-down 4 向；isometric 慣例 8 向是美術量地獄（iso 的隱藏成本，選視角時要一起算——見 `../../../architecture/game-architecture/references/algo-2d-projection-and-grids.md`）。
- **左右翻面省一半**：不對稱設計（單肩包、單手武器）會讓翻面穿幫——角色設計期就決定要不要對稱。
- 骨骼在多朝向下優勢放大：正/側/背三套 rig 各自動作沿用，逐幀是 8 向全額重畫。

## Spritesheet 規格紀律（選了逐幀就守）

- **幀尺寸統一、pivot 統一在腳底**——pivot 亂，y-sort 排序與位移全抖（與 2D 排序篇的資產規格是同一條）。
- **命名即資料**：`walk_s_00..n`（動作_朝向_幀序）——載入器靠名字組動畫，規則進 `content-asset-conventions.md`。
- **攻擊判定幀是資料不是感覺**：哪一幀出判定、哪一幀可取消，標進動畫資料（`anim-game-principles.md` 的前搖後搖落地）。

## 常見坑

- **後期加動作才發現成本模型**：逐幀專案第 15 個動作做不動了——立項時用「動作清單 × 朝向 × 幀數」估總量再選路線。
- **骨骼果凍感**：所有部件都掛平滑曲線、沒有一幀到位的硬變化——關鍵幀該硬就硬，骨骼也能做打擊感。
- **兩路線混用無邊界**：同畫面骨骼角色與逐幀角色風格打架——混搭規矩進風格指南。
- **Spine 授權當免費**：editor 按席位收費、runtime 授權跟發行綁——外包給誰、誰要有 license，發案前談清楚（外包交付規格見 `content-outsourcing-handoff.md`）。
- **外包骨骼檔沒約定版本**：Spine editor 版本與遊戲 runtime 不匹配，檔案打不開或行為不同——版本寫進交付規格。
