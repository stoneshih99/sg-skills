# 數值設計（Numeric Design）

把體驗目標翻譯成公式與表格。鐵律：**數字服務體感，不是反過來**——先定「幾刀殺一隻雜兵、幾分鐘升一級」的體驗目標，再推公式；直接在表裡填數字的專案，平衡永遠在打地鼠。宏觀經濟結構（source/sink）見 `gdd-progression-economy.md`，這篇是它底下的數學層。

## 基準錨點法：一切相對推導

先定**基準單位**，其他一切相對它換算：

```
錨點（範例）:
    基準玩家 = 1 級、無裝備
    基準怪   = 等級同玩家的雜兵
    體驗目標 = 基準玩家殺基準怪 4 刀（TTK ≈ 3 秒）
              基準怪殺基準玩家 8 刀（容錯 8 次失誤）

由此推導:
    怪 HP  = 玩家攻擊 × 4
    怪攻擊 = 玩家 HP ÷ 8
    精英 = 基準怪 ×3 血 ×1.5 攻（= 更久更痛，但不是「更海綿」）
```

- **錨點是全表的地基**：所有數值都是「錨點的倍數」，調體感只動錨點與倍率，不逐格改表。
- 錨點要穩：中途改錨點 = 全表重推——所以錨點定案前用灰盒玩測驗過（幾刀殺的體感，見 `../../game-production/references/milestone-stage-definitions.md` 的切片期）。

## 戰鬥數值三角：EHP / DPS / TTK

```
TTK（擊殺時間）= 對方 EHP ÷ 我方 DPS
EHP（有效血量）= HP ÷ (1 - 減傷率)
```

- **TTK 是體驗參數**：快節奏動作 1-3 秒、射擊 0.2-1 秒、MMO 十秒級——先從遊戲類型定 TTK 目標，回推 HP 與傷害的量級。
- **攻防公式選型**（成長體感差異大，第一天選定）：

| 公式 | 形狀 | 體感 | 風險 |
|------|------|------|------|
| 減法：`傷害 = 攻 − 防` | 防禦線性起效 | 「破防」感強烈、裝備跳變明顯 | 攻 ≤ 防時傷害歸零——需保底傷害 |
| 除法：`傷害 = 攻 × 攻/(攻+防)` | 平滑遞減 | 成長平順、永不歸零 | 缺乏戲劇性節點 |

- **屬性折算表**：每個屬性換算成「等效 DPS 或等效 EHP」（1 點力量 = 2 DPS、1 點體質 = 15 EHP）——這張表是 cost curve 的地基，也是「暴擊率跟攻擊力哪個划算」有標準答案的前提。

## 成長曲線：公式選型

需求指數、產出線性的骨架承 progression-economy，公式層的選擇：

| 公式 | 用在 | 體感 |
|------|------|------|
| 線性 `a·x` | 單場內資源、短線成長 | 穩定、無加速感 |
| 多項式 `a·x^n`（n≈1.5-2.5） | 升級經驗需求 | 前快後慢、常用甜區 |
| 指數 `a·b^x` | 放置/掛機的數值膨脹 | 加速感強、後期數字爆炸 |
| 分段 | 章節制成長（換章跳一階） | 可控、配合內容節點 |

- 曲線先畫再填表：試算表把曲線圖畫出來看形狀（成長的「可感時刻」落點對不對，見 progression-economy 的寧可少次而大顆）。

## Cost Curve / Power Budget：平衡的可審計性

每件裝備 / 技能 / 單位有**能力預算**，屬性按折算表計價：

```
5 級武器預算 = 100 點
    +30 攻擊（60 點）+10% 暴擊（30 點）→ 已用 90 點 → 合格
    某武器算出來 135 點 → 超模——不是「感覺太強」，是可計算的超標
```

- **平衡從「感覺」變成「審計」**：新內容上線前跑一遍預算檢查（可腳本化——表都在 config，見 `../../game-architecture/references/data-config-driven.md`）。
- 特效類屬性（吸血、反傷）折算不進公式時，給**風險係數**（條件觸發的價值 × 觸發率估計）——粗略但可比較，勝過完全憑感覺。
- 刻意超模是合法設計（版本賣點、成長獎勵）——但要**知道超了多少**，超模是決策不是事故。

## 試算表工作流：表是模擬器

- **參數頁集中**：錨點、係數、公式參數全部在一頁——調平衡只動這頁，其他頁全是公式引用（魔法數字散在各格 = 改一漏三）。
- **模擬頁**：輸入等級/配裝，輸出 TTK、成長時間線——填數字前先看模擬結果。
- **曲線頁**：關鍵曲線全部圖表化——形狀錯誤（成長斷崖、需求爆炸）看圖一眼抓。
- **落地**：試算表定案 → 匯出成遊戲 config 表（單一真相是試算表還是 config 要選一邊，通常：設計期試算表、上線後 config 回頭同步）——載入驗證接 data-config-driven 的 schema。
- **自動化驗證**：傷害管線是純函數（`../../game-architecture/references/system-action-combat.md`）就能 headless 跑模擬戰鬥——批次驗證「1-50 級每級打同級怪的 TTK 曲線」，比手玩五十次準。

## 驗證閉環

數學對了不等於體感對了：模擬驗曲線 → 玩測驗體感（`playtest-hypothesis-and-metrics.md` 的行為指標：實際 TTK、卡關等級分佈）→ 上線後遙測驗大盤（`../../game-tooling/references/telemetry-funnels-retention.md` 的關卡熱區與經濟監控）——三層各驗各的，缺一層就有盲區。

## 常見陷阱

- **直接填數字不建公式**：每格手填的表無法整體調整——第一天就用錨點推導。
- **攻防公式中途換**：減法換除法 = 全部裝備價值重算——選型是第一週決策。
- **5% 的無感提升**：折算精確但玩家無感（見 progression-economy 的可感原則）——數值設計的顆粒度要對齊感知閾值，寧可少次大顆。
- **nerf 補丁循環**：超模了 nerf、nerf 完別的超模——沒有 cost curve 的平衡是打地鼠；先建預算基準再談個案。
- **試算表與 config 雙真相**：兩邊各自改、漂移到對不上——指定單一真相與同步方向。
