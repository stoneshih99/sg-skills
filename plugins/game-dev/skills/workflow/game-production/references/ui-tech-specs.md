# UI 技術規格

UI 的技術債特別隱蔽：單看每個畫面都沒事，疊起來就是適配地獄與效能黑洞。規格先立，數字進 content-production 的規格表。

## 解析度與比例適配

- **設計基準解析度**：定一個基準（如 1920×1080），所有 UI 以此設計，其他解析度用縮放策略——基準沒定，每個 UI 各自為政。
- **比例範圍要定**：支援的最寬（21:9）與最窄（手機直式？16:10 掌機？）比例第一天定——**寬螢幕靠邊錨定、窄螢幕重新佈局**，兩種策略的邊界寫清楚。
- **錨定規則**：每個 UI 元素聲明錨點（角落/邊/中心）與縮放行為（跟隨縮放/固定尺寸）——HUD 錨四角、彈窗錨中心是基本盤。
- **安全區（safe area）**：電視 overscan、手機瀏海與圓角——可互動元素一律在安全區內，規格表寫百分比（見 `art-asset-types.md` 的 UI 安全區）。

## 自動排版

- **文字容器自動尺寸 + 佈局群組**：字級可調（見 `ui-accessibility.md`）與多語膨脹（見 `loc-layout-and-fonts.md`）都依賴它——寫死像素座標的 UI 兩者皆敗。
- **極端測試組合**：最長語言 × 最大字級 × 最窄比例——三個極端同時上，活下來才算適配完成。

## UI 效能

UI 是隱形的效能大戶，常見熱點（對照 `../../../tools/game-tooling/references/perf-common-hotspots.md`）：

- **重建（rebuild/reflow）**：改一個文字觸發整個畫布重排——**動態元素與靜態元素分開容器**（每幀跳的傷害數字、計時器隔離到自己的小畫布），別讓一個計時器拖著全 HUD 重排。
- **每幀更新的 UI**：血條、計時器用髒標記（值變才更新，見 optimization-playbook 的 dirty flag）——每幀 set text 是每幀配置 + 每幀重建的雙重罪（字串配置見 common-hotspots 的 GC 段）。
- **draw call**：UI 圖集化（見 `art-tech-specs.md` 的圖集）、同圖集的元素連續繪製；全螢幕半透明面板注意 overdraw。
- **隱藏 ≠ 停用**：看不見的選單若還在排版與更新，白付；關閉的 UI 真正停用（disable 而非 alpha 0）。

## 常見陷阱

- **只在開發機的解析度測**：16:9 完美、21:9 血條飄進畫面中央——CI 或驗收含多比例截圖（可掛進 `build-automation.md` 的煙霧測試）。
- **UI 縮放用整體 scale 硬縮**：4K 下把 1080p 的 UI 放大兩倍，字糊圖糊——向量化排版 + 高解析資產分級。
- **彈窗疊彈窗無管理**：層級（sorting）各自為政，新彈窗被舊的蓋住——UI 層級表全專案一張（背景 HUD < 選單 < 彈窗 < 系統提示），同 audio 的 bus 思維。
- **效能等出事才管**：UI 重建的 spike 混在遊戲邏輯裡難歸因——UI 獨立一個計時桶（見 measurement-first 的計時面板），退化當天可見。
