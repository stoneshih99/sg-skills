# 版面與字型

翻譯回來破版，責任多半不在譯者——是版面沒留彈性。這篇講怎麼讓 UI 吃得下任何語言，以及字型怎麼規劃。

## 文字膨脹

同一句話的長度因語言而異，**以英文為基準**的常見膨脹率：

| 語言 | 相對長度 |
|------|---------|
| 德文 / 俄文 / 法文 | +20% 到 +35%（短句可達 +100%：「OK」→「Bestätigen」） |
| 中文 / 日文 / 韓文 | −30% 到 −50%（但行高更高） |
| 泰文 / 越南文 | 上下標符號堆疊，行高需求大 |

版面對策：

- **UI 以「最長語言 + 30%」設計**：按鈕、選單欄寬留膨脹空間——以中文原文設計的緊湊 UI，出英文德文必破。
- **短句膨脹最兇**：按鈕、標籤這種 1-3 個詞的地方最危險，偏偏它們的空間最緊。
- **溢出策略每個元件定死**：換行？縮字級？截斷加省略號？捲動？——「沒定義」的結果是引擎隨機選一種醜法。縮字級要設下限（低於可讀性下限寧可換行）。
- **九宮格與自動佈局**：面板用可拉伸結構（見 `art-asset-types.md` 的九宮格）、文字容器用自動尺寸——寫死像素寬的文字框是破版預定。

## 偽本地化（Pseudo-localization）

**翻譯前**就把版面問題抓完的測試法：把所有字串機器替換成「加長 + 特殊字元 + 標記」的假翻譯：

```
"Start Game" → "[Šţàŕţ Ĝàɱè ẋẋẋẋ]"
                ↑重音字元測字型   ↑加長 30% 測膨脹  []測截斷
```

- 一鍵切換偽本地化語言（做成 debug 指令，見 `../../../tools/game-tooling/references/debug-console-and-cheats.md`），全遊戲跑一遍：
  - 破版、截斷 → 版面問題
  - 方塊字（tofu）→ 字型缺字
  - 顯示英文原文 → 漏外化的字串（**最有價值的發現**，見 `loc-text-externalization.md`）
- 在 alpha 就跑，別等翻譯回來才發現 200 處破版。

## 字型規劃

- **覆蓋率先查**：目標語言的字元集（拉丁擴展、西里爾、CJK、泰文）你的字型有沒有——風格再美缺字就是方塊。CJK 字型檔大（MB 級），行動平台注意記憶體與載入。
- **Fallback 鏈**：主字型缺字時退到備援字型——鏈要配置並實測，別依賴引擎預設（預設 fallback 的風格通常突兀）。
- **每語言可覆寫字型與排版參數**：字型、字級縮放、行高做成 per-locale 設定（資料驅動）——CJK 常要 +10-20% 行高，泰文更多。
- **風格字型的取捨**：手寫體/像素體常只有拉丁字元——標題用風格字型 + 內文用高覆蓋字型的雙軌制，或接受 CJK 版標題換字型。
- **RTL（若支援阿拉伯文/希伯來文）**：不只文字反向，整個 UI 鏡像（返回鍵位置、進度條方向）——支援與否**第一天決定**，事後加是 UI 重寫等級。

## 非文字的本地化彈性

- **語音與字幕**：字幕獨立於語音存在（配 `audio-mixing-loudness.md` 的 Voice bus）；語音本地化成本極高，多數專案「介面全翻、語音原音+字幕」。
- **圖內文字**：真的必須進圖的字（logo、招牌），資產按 locale 分版（`_zh`、`_en` 後綴進命名規範，見 asset-conventions）。

## 常見陷阱

- **只用自己語言測版面**：中文最短，用中文測出來的 UI 是最寬鬆的假象。偽本地化 + 德文是照妖鏡。
- **字級縮到不可讀**：溢出全靠縮字級，德文版整個 UI 字小 40%——縮級設下限。
- **字型 fallback 沒實測**：上線後泰文玩家截圖全是方塊。每個支援語言至少全選單走一遍。
- **硬編碼的排版假設**：「名字最多 4 個字」「標題一定一行」——這些假設在別的語言全部陣亡。用極端案例驗收（同 asset-type-guidelines 的極端內容原則）。
