# 預測與延遲補償（Prediction & Latency）

權威在伺服器、體感在客戶端——中間隔著 RTT。這篇是把「等伺服器回覆才動」的 100ms+ 遲鈍，變成「按下就動」的體感魔術。動作遊戲的連線手感成敗全在這層（手感預算見 `../../game-design/references/feel-input-responsiveness.md` 的 100ms 鐵律——網路遊戲靠預測來守住它）。

## 本地預測 + 和解（自己的角色）

```
每幀：
1. 取樣輸入 → intent（帶遞增序號 n）
2. 立刻本地模擬（不等伺服器）→ 存 (n, intent, 預測後狀態) 進環形緩衝
3. intent 上行

收到伺服器權威狀態（含「已處理到序號 k」）：
4. 對比緩衝裡序號 k 的預測狀態
5. 一致 → 丟棄 ≤k 的緩衝，繼續
6. 不一致 → 回滾到權威狀態，重放緩衝裡 k+1..n 的 intent（和解 reconciliation）
```

- **intent 分層是前提**（`system-3c.md`）：預測 = 本地先跑一遍同一套 Character 邏輯；沒有 intent 層的專案做不了預測。
- **和解的修正要平滑**：回滾重放後的位置差不要瞬移——小誤差在幾幀內插值收斂，大誤差（被權威判定撞牆）才瞬移。閾值是手感參數。
- **模擬必須可重放**：Character 更新只依賴（狀態, intent, dt）——藏在 update 裡的隨機數與全域讀取會讓重放結果漂移（決定論的小範圍版，見 `data-network-sync.md`）。

## 其他實體：插值為主

別人的角色你沒有他的輸入，預測不了——改用**延遲插值**：

- 收到的快照不立刻套用，放進緩衝；渲染時間 = 伺服器時間 − 插值延遲（約 2-3 個快照間隔，如 100ms）——永遠在兩個已知快照之間插值，移動絲滑。
- **代價是你看到的別人是 100ms 前的**——這筆帳由延遲補償來平（見下）。
- 緩衝空了（連續丟包）才**外推（extrapolation）**：沿速度前推，設短上限（~200ms）——外推越久越錯，超時寧可凍結也不要讓角色飛出懸崖再彈回來。
- 插值的是**狀態不是動畫**：位置/朝向插值，動畫由狀態驅動本地播放（見 `../../game-production/references/anim-game-principles.md` 的狀態機驅動）。

## 延遲補償：伺服器回捲判定

問題：你瞄準的是插值延遲下「100ms 前的他」——伺服器用「現在的他」判定，你明明瞄準了卻 miss。

**解法**：伺服器保留最近 N 幀的 hurtbox 歷史；收到射擊時，**回捲到射擊者當時看到的時間**再判定：

```
on_shoot(shooter, shot_time):
    rewind_time = shot_time            # = 伺服器時間 - shooter的插值延遲 - 半個RTT
    for target in candidates:
        hurtbox = target.history.at(rewind_time)   # 回捲的碰撞盒
        raycast(shot, hurtbox)                     # 判定用回捲後的位置
```

- **這是公平的轉移不是消除**：射擊者「所見即所得」，代價是被打者體驗「進掩體後還被打死」——回捲上限（150-250ms）是這個取捨的旋鈕，超過上限的高延遲玩家自己吸收誤差。
- 命中判定的資料結構承 `system-action-combat.md`（hurtbox 歷史 = 每 tick 的快照環形緩衝——又是純資料的紅利）。

## 哪些行為可以預測：分類準則

不是所有動作都該預測。準則：**可回滾、且回滾在視覺上可掩飾的，才預測**。

| 行為 | 預測？ | 理由 |
|------|--------|------|
| 移動、跳躍 | ✅ | 誤差小、插值可掩飾 |
| 攻擊起手（動畫+音效） | ✅ | 前搖期間等權威確認，被拒絕就中斷——玩家極少察覺 |
| 命中結算（扣血、擊殺） | ❌ 等權威 | 回滾「你殺了他」是災難級體驗 |
| 拾取、開箱、購買 | ❌ 等權威 | 經濟事務冪等且不可逆——UI 轉圈半秒可接受 |
| 技能冷卻開始 | ✅ | 本地先轉冷卻，被拒絕再退還（見 `system-skill.md` 的階段機） |

- 表現與結算分離（combat 篇的「回饋只聽結算事件」）在網路下升級為：**預測的是表現，權威的是結算**。

## 除錯

- 網路模擬常開（延遲/抖動/丟包注入，`../../game-tooling/references/debug-console-and-cheats.md`）——預測 bug 只在爛網路下現形。
- debug draw 三重影：本地預測位置、伺服器權威位置、對方插值位置同屏顯示（`../../game-tooling/references/debug-draw.md`）——三者的偏差一眼定位是預測錯、和解錯還是插值錯。
- 和解頻率上 watch 面板：頻繁大幅和解 = 客戶端與伺服器模擬漂移，去查決定論。

## 常見陷阱

- **預測了不可回滾的事**：本地先扣錢買道具，權威拒絕後回滾——玩家看到錢包跳動，信任崩潰。照分類準則。
- **和解瞬移**：每次修正直接 set position——高延遲玩家的角色持續抽搐。平滑收斂 + 閾值。
- **插值延遲設成 0**：「我要最即時的資料」——快照間隙全靠外推，別人的角色永遠在抖。插值延遲是體感的地基稅。
- **只補償射擊不補償近戰**：近戰判定也吃延遲——回捲判定同樣適用（範圍判定回捲成本更高，上限可更嚴）。
- **好網路開發症候群**：與協定篇同一條——**這層的一切只在爛網路下才看得見**。
