# VFX 設計

特效的「廉價感」九成出在時間結構，不是貼圖解析度。好特效是一個微型敘事：預告 → 爆發 → 消散，每段有自己的職責。

## 三段時間結構

```
[預告 anticipation]   →  [爆發 burst]        →  [消散 dissipate]
 聚氣、吸入、亮點匯聚      最亮最大的 1-3 幀        碎片、煙、餘光淡出
 佔時 20-40%              佔時 5-10%              佔時 50-70%
```

- **爆發要「瞬間」**：最大最亮只存在幾幀——拉長爆發 = 糊掉的閃光。跟音效瞬態同一個道理（見 `audio-sfx-design.md` 的瞬態層），而且**同一幀觸發**（見 impact-feedback 的同步原則）。
- **消散最長但最收斂**：亮度與飽和度快速衰減，只留形狀殘影——消散段搶戲，畫面就永遠是滿的。
- **預告是可讀性工具**：敵人技能的預告段就是 telegraph（見 `art-visual-readability.md`）——時長由 gameplay 定（給玩家的反應時間），不由美術定。

## 形狀語言

- **輪廓決定辨識**：火球、冰刺、毒霧在剪影下就要分得出來——特效也過剪影測試（同 visual-readability）。
- **方向性**：打擊特效沿攻擊方向噴、受擊特效從命中點放射（見 `../../../planning/game-design/references/feel-impact-feedback.md` 的命中點原則）——全向對稱的特效沒有力的方向，就沒有力。
- **軌跡跟動畫弧線走**：揮擊拖尾（trail）貼著動畫的弧（見 `anim-game-principles.md`），分家就假。
- **大小 = 重要性**：特效尺寸跟著 gameplay 量級走（小技能小、絕招大）——全都全螢幕，玩家就分不出哪招要躲。

## 色彩職責

- **特效色是功能色**：陣營（我方藍綠 / 敵方紅橙）、屬性（火紅 / 冰藍 / 毒綠）、狀態（增益金 / 減益紫）——先分配功能，再談好看；被裝飾用掉的功能色會讓戰場不可讀（見 visual-readability 的功能色專用）。
- **亮度層級**：核心最亮 → 主體 → 邊緣漸暗；貼圖自帶的白心 + 色彩外圈是最通用的結構。
- **配合場景曝光**：特效在最暗與最亮的場景各看一次——HDR/bloom 設定會放大特效亮度，別只在標準場景調。

## 與遊戲事件的綁定

- 特效觸發走事件表（與音效同一張，見 `audio-implementation.md` 的事件 → 資產對照）——「一個 gameplay 事件 = 音效 + 特效 + 震動」在同一筆資料裡，同步自然成立。
- 持續型特效（buff 光環、燃燒）要有明確的開始/循環/結束三態資產——只做循環段的特效，開關時會「彈出彈進」。

## 分級與節制

- **特效量級對齊回饋量級**：普攻小、暴擊中、絕招大（見 impact-feedback 的分級原則）——並留「上限預算」：同屏特效的總亮度/總面積有帽子，超過就是互相抵消。
- **別人的畫面權重**：多人/混戰下，自己的特效全尺寸、隊友的縮小淡化、敵人的預警全保留——優先序即 gameplay 資訊價值。
- 驗收永遠用最吵場景：最多單位 + 最多技能同時放（同 visual-readability 的高峰場面測試）。

## 常見陷阱

- **用粒子數堆存在感**：500 顆糊成雲不如 30 顆有形狀——形狀語言 > 數量（效能也謝謝你，見 `anim-vfx-tech-specs.md`）。
- **每個特效都想當主角**：全部又大又亮 = 視覺軍備競賽（同 visual-readability 的零和原則）。
- **只在編輯器裡調**：特效編輯器黑背景 + 單發播放，跟實際戰鬥完全兩回事——進遊戲、連發、疊加著調。
- **消散段偷懶硬切**：爆發完直接消失，「廉價感」的第二大來源（第一是爆發拖太長）。
