# UI Spec: <名稱>

## Reference Boundary

記錄參考來源、權利或授權依據、可精確重製或可借用的範圍，以及未確認權利而不可複製的品牌、內容或素材。

## Goal And Audience

說明此介面要完成的使用者目標、主要受眾與目標平台。

## Evidence

列出能支持本規格的參考證據，並標示其來源類型。

### Observations

只記錄可由參考直接確認的結構、內容、樣式、狀態或行為。

### Assumptions

明確標示為補足缺失參考而做的假設，包含未提供的裝置或狀態。

## Information Architecture

列出頁面區域、資訊群組、導覽關係與使用者閱讀優先順序。

## Layout And Hierarchy

定義區塊位置、尺寸關係、留白與視覺層級的可驗收規則。

## Type And Color System

定義字級角色、字重、對比與色彩用途，不臆測未見的精確 token。

## Components And Content

列出元件、必要內容、互動入口與各元件的責任。

## Assets

列出需要提供、可重用或必須原創的圖像、圖示、字體與資料來源。

## State Matrix

列出每個元件的預設、hover、focus、loading、empty、error 與成功狀態。

## Motion

描述可觀察的轉場目的、觸發條件與視覺結果，不指定動畫技術。

## Responsive Behavior

定義各平台或寬度下的重排、隱藏、替代導覽與內容優先順序；缺少參考時標示為假設。

## Accessibility

定義鍵盤、焦點、語意、對比與降低動態效果的驗收要求。

## Performance

定義載入、媒體、骨架畫面與版面穩定性的可驗收預算或限制。

## Anti-Patterns

列出不可出現的誤用、品牌複製、資訊層級或互動問題。

## Acceptance Checks

列出工程師可逐項檢查的視覺、內容、狀態、響應式與可近用性條件。

## Open Inputs

列出仍會阻擋實作的缺失資訊；空白表示沒有阻擋輸入剩餘。
