# Tile-based 製作規範（Tileset / Tilemap Standards）

Tile-based 的生產力來自一件事：**磚是標準件**——規格有紀律，關卡就是快速組裝；規格飄了，每張地圖都是手工藝品。磚尺寸與接縫驗收的基礎在 `art-asset-types.md` 的 Tilemap 節，這篇是完整規範：tileset 檔案規格、autotile 模板、層結構、tile 屬性資料、編輯工作流。grid 數學與 iso 投影見 `../../game-architecture/references/algo-2d-projection-and-grids.md`；Unity 落地見 **sg-unity-dev-skills** 的 unity-runtime 2d 家族。

## Tileset 檔案規格

- **磚尺寸全專案一個**（16/32/48，第一天定死——`art-asset-types.md`）；tileset 單檔 ≤2048px，按主題分檔（terrain / props / interior…）。
- **每磚外擴 1-2px（extrude/bleed）**：相機落在半像素時取樣吃到鄰磚，畫面出現閃爍縫線——**磚縫閃線是 tile 遊戲第一名視覺 bug**，資產期解掉最便宜。
- **磚位即 id，發佈後不可移動**：關卡資料存的是磚在圖集內的位置——中途插磚、重排，所有用過的關卡整張錯位。**只能往後追加**，廢棄磚留空洞不回收。這是 tile 遊戲的 schema 相容問題（與存檔版本遷移同性質）。

## Autotile（規則磚）：按標準模板產出

- **超過一張測試圖的量就該 autotile**——手鋪邊角磚的錯誤率隨地圖數量線性成長。
- 兩套業界標準模板，美術按模板出圖、別自創排列（引擎與外部工具的 autotile 都只吃標準模板）：

| 模板 | 看什麼 | 夠用於 | 不夠時 |
|------|--------|--------|--------|
| **16 磚（4-bit）** | 上下左右四鄰 | 粗地形、方正結構 | 內角會缺——出現「斜接縫」 |
| **47 磚（8-bit blob）** | 含對角八鄰 | 圓角地形、細窄通道、完整內外角 | 製作量是 16 磚的三倍 |

- **地形轉接磚是 O(地形對數) 的成本**：草→沙、草→水、沙→水各一組——**用「相鄰規則」控制成本**（設計上禁止某些地形直接相鄰，中間必隔一種），這是省美術量的設計手段，不是技術限制。

## 層結構：每張地圖同一套層

```
overlay    樹冠、屋頂——蓋在角色上（進出時淡出）
obstacle   遮擋物——參與 y-sort 排序
deco       貼地裝飾——不遮擋、不碰撞
ground     地面——永遠最底、整片合批
collision  █ 不可見資料層：碰撞
logic      █ 不可見資料層：觸發區、spawn 點、尋路標記
```

- **視覺層與資料層分離是鐵律**：碰撞與觸發是隱形資料層，**不從視覺磚反推**（「這磚看起來是牆所以是牆」——換皮、加特例磚就崩）。
- **層名是介面**：載入器與工具靠層名工作——每張地圖同一套名字，規則進 `content-asset-conventions.md`，不准即興加層。

## Tile 屬性資料驅動

- **tile id → 屬性表**（可走、移動成本、材質音效、可破壞…）外部表驅動（`../../game-architecture/references/data-config-driven.md`）——程式裡 `switch(tileId)` 是第 50 種磚時的災難。
- 尋路直接吃 collision＋cost 層——tilemap 本身就是尋路圖（`../../game-architecture/references/algo-search.md` 的 grid 圖）。

## 編輯工作流選型：內建 vs 外部編輯器

| 路線 | 優勢 | 代價 |
|------|------|------|
| **引擎內建**（palette 類） | 就地預覽、引擎物件直掛（tile 帶光源/prefab） | 關卡=場景檔，diff 難、版本衝突重、跨工具處理弱 |
| **外部編輯器**（LDtk / Tiled） | 關卡資料是乾淨 JSON——可 diff、可程序處理、關卡設計與引擎解耦 | 要維護 importer、引擎端互動要橋接 |

**裁決**：關卡量大、要程序化處理關卡資料、或多人分工 → 外部（2D 新專案 LDtk 是現代預設）；關卡少、tile 與引擎元件深度互動 → 內建。**一關一檔**進版控（衝突隔離，`build-version-control.md` 的場景衝突對策同理）。

## 常見坑

- **磚縫閃線**：沒 extrude——資產期外擴，別在引擎端拿縮放硬扛。
- **tileset 中途插磚**：舊關卡全部錯位——只追加、不重排。
- **視覺磚當碰撞來源**：資料層分離。
- **層名自由發揮**：工具鏈全靠 if-else 接特例——層名規範化。
- **autotile 自創模板**：工具吃不了，回頭手鋪。
- **轉接磚組合爆炸**：沒立相鄰規則，美術量隨地形種類平方成長。
