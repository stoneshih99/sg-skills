# UI Build Brief: <名稱>

## Source Spec

列出本次實作依據的 UI spec、wireframe 或 design brief，並標示仍待確認的規格。

## Target Repository And Route

寫明目標 repository、route 或 screen，以及本次可修改的檔案與範圍。

## Existing Stack And Instructions

記錄已確認的技術棧、專案 instructions、可執行 scripts 與不可假設的能力。

## Design System And Reuse Map

列出 UI design system、既有 tokens、components、assets、資料存取與樣式慣例；逐項對應可直接重用、需要擴充與確定缺少的部分。

## Content And Data

定義畫面需要的內容、資料來源、loading 時的呈現及允許使用的 mock 資料。

## Component And State Map

逐一對應元件與 default、hover、focus、loading、empty、error、success 等必要狀態。

## Deterministic Test States

列出需要固定的 data、time、locale、timezone、theme、animation 與 network outcome，以及沿用的 fixture、Storybook、test route 或 mock。

## Verification Triggers

| Viewport／theme | State | Reproduction trigger | Expected stable result |
|---|---|---|---|
| | | | |

## Responsive Requirements

定義目標 viewport、重排、溢位處理與各尺寸下的內容優先順序。

## Accessibility And Reduced Motion

定義鍵盤、焦點、語意、對比與 reduced-motion 的可驗收行為。

## Delivery Form

說明交付的是 route、screen、元件、資產或驗證紀錄，並明示是否包含使用者要求的部署。

## Non-Goals

列出本次不改動的產品範圍、設計方向、技術棧與部署事項，作為實作邊界。

## Verification Commands

列出要實際執行的啟動、build、lint、test 或其他驗證 commands 與預期結果。

## Completion Evidence

分開列出已實際執行且確認的 commands、已檢查的畫面或截圖；不可把計畫中的檢查寫成完成證據。

## Unverified Items

逐項列出尚未驗證、需要其他環境或使用者決定的項目；沒有項目時明確寫「無」。
