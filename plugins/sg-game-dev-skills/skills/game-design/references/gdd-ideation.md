# 創意發想與立項（Ideation）

從零到「值得立項的點子」。原則先立：**想法便宜，立項貴**——立項意味著接下來幾個月的時間押注，所以這篇的重點不是「怎麼想出點子」（方法很多），是**怎麼篩掉不該立項的點子**。

## 點子的合法形狀

一個能往下走的遊戲點子必須說得出三件事：

```
核心幻想    玩家在扮演什麼、體驗什麼情緒（狩獵巨獸的渺小與征服）
核心動詞    玩家實際反覆在做什麼（瞄準弱點、閃避、部位破壞）
差異鉤子    為什麼玩你的不玩已存在的那款（見 gdd-positioning.md 的一句話格式）
```

- **說不出核心動詞的是題材不是點子**：「殭屍末日生存」是題材；「用聲音引開殭屍的潛行」才是點子。題材可以換皮，動詞才是遊戲。
- 三件事寫不滿一頁就別開會討論——先回去補齊形狀。

## 生成方法（挑順手的用）

- **機制移植**：把 A 類型的核心機制搬進 B 類型（卡牌構築 × 地城爬行 = Slay the Spire）——最高產的一招，因為兩邊都是驗證過的樂趣。
- **參照變形（X but Y）**：拿一款你熟的遊戲，改變一條根本規則後推演全局（「魂系戰鬥，但死亡的屍體變成下一輪的敵人」）——變形的規則離核心越近，差異越真。
- **限制驅動**：給自己硬限制（單鍵操作、無文字、十分鐘一局）——限制殺掉慣性選項，逼出結構性創新。jam 出好點子的原因就是這個。
- **痛點反轉**：你玩某類型時最煩的一件事，把它變成設計核心解掉（討厭刷素材 → 素材全自動、樂趣移到配裝決策）。

生成期的紀律：**量大於質、先發散不評判**——列 20 個爛點子再篩，好過守著第一個點子拋光。

## 篩選漏斗（立項的三道關）

**第一關：快篩（自問，五分鐘一個）**

- [ ] 我自己想玩嗎？（不想玩的東西撐不過開發低谷）
- [ ] 說得出「哪個瞬間好玩」嗎？（說不出 = 幻想在題材不在玩法）
- [ ] 核心動詞我做得出來嗎？（技術與資源的誠實評估）
- [ ] 範圍量級對嗎？（單人做 MMO 直接出局——見 `gdd-scope-cutting.md`）

**第二關：定位測試**——用 `gdd-positioning.md` 的一句話 + mockup 找 3 個目標受眾測 3 秒反應。過濾掉「只有自己覺得有趣」的點子。

**第三關：樂趣驗證**——核心動詞的灰盒原型（見 `gdd-risk-assessment.md` 的樂趣風險與 `../../game-production/references/milestone-stage-definitions.md` 的 prototype 殘酷規則）。**三關全過才立項**；第三關不過的點子回收進點子庫（動詞可能對、包裝錯了）。

## 立項的產出

通過三關後，立項 = 填出 `../templates/gdd-one-pager.md` + 定第一個里程碑（`../../game-production/references/milestone-planning-and-estimation.md`）。one-pager 填不順的欄位就是還沒想清楚的地方——它是立項的體檢表。

## 常見陷阱

- **題材當玩法**：「我要做賽博龐克版的 XX」——換皮不是點子，動詞沒變就沒有新遊戲。
- **縫合怪**：「有生存、有構築、有 rogue、有種田」——每多縫一個類型，範圍翻倍、認知負擔翻倍，而樂趣不相加。一個核心動詞，其他都是配菜（見 `gdd-mechanics-design.md` 的核心優先）。
- **愛上第一個點子**：跳過生成期直接立項——第一個點子通常是最平庸的（它是慣性的產物）。強制自己列滿替代方案再選。
- **用熱情代替驗證**：「我超想做這個」不是立項理由，三關才是——熱情是燃料，不是方向盤。
- **點子保密症**：怕被抄襲不給人看——執行才是壁壘，回饋比保密值錢。
