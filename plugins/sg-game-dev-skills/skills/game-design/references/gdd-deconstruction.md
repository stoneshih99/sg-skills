# 參考作拆解（Deconstruction）

`gdd-ideation.md` 的兩個最高產生成法——機制移植、X but Y——都預設你「懂」那款參考作。**懂不是玩過，是拆得出來**：說得出它的循環、經濟、釣子在哪。這篇是拆解方法：拆什麼、怎麼拆、怎麼轉成立項輸入。原則先立：**拆解是立項工具不是學術研究**——拆 2-3 款、產出三張表就停。

## 拆解要回答的三個問題

1. **樂趣引擎**：哪個瞬間好玩、為什麼重複一百次不膩？
2. **留人結構**：前 30 分鐘做了什麼讓人留下、長期鉤子是什麼？
3. **我的行動**：搬什麼、避什麼、它的玩家還缺什麼？

拆完答不出這三題，等於沒拆。

## 拆什麼：五個切面

| 切面 | 拆法 | 對照篇 |
|------|------|--------|
| **核心循環** | 三圈拆：動詞層（秒）→ 局層（分）→ 成長層（小時），每圈記「決策點＋回饋」；畫成循環圖 | `gdd-core-loop-design.md` |
| **經濟** | source/sink 表 + 卡點位置（等待/付費/技術門檻設在哪、為什麼設在那） | `gdd-progression-economy.md`；圖法見 `../../game-diagrams/references/economy-flow-diagram.md` |
| **前 30 分鐘時間軸** | 逐段記「讓我做什麼/教什麼/給什麼」；標出第一次「哇」在第幾分鐘、第一個可分享瞬間在哪 | `level-teaching-through-design.md` 的四段教學法當對照尺 |
| **回饋堆疊** | 挑一個核心動作（一次攻擊/一次過關），列出它疊了幾層回饋——拆「為什麼它做起來爽」 | `feel-impact-feedback.md` |
| **機制相互作用** | 機制清單 × 相互作用矩陣——樂趣在交叉格，不在單格 | `gdd-mechanics-design.md` |

## 怎麼拆：紀律

- **玩兩輪，角色分開**：第一輪當玩家——只記情緒時間戳（興奮/無聊/困惑/挫折），**不分析**（分析模式會殺掉體驗訊號）；第二輪當拆解者——帶著上面五個切面慢玩、隨時暫停記錄。
- **無聊點跟爽點一樣值錢**：它在無聊段做了什麼讓你撐過去（小目標？變化？懸念？）——那就是設計。
- **拆「決策」不拆「內容」**：記玩家面對的選擇與代價，不是數它有幾把武器——功能清單不是拆解。
- **讀一星評論**：差評區是免費的痛點清單——`gdd-ideation.md` 痛點反轉的原料、`gdd-positioning.md` 競品空隙的證據來源。
- **失敗的同類作也拆**：它試了什麼沒成、為什麼——失敗作用最低成本告訴你坑在哪，只拆成功作會倖存者偏差。

## 轉成立項輸入：三張表

```
借鑑清單    搬什麼 + 它為什麼成立（結構性理由，不是「因為它紅」）
反面清單    明確不做什麼（它的哪些設計不服務我的核心動詞）
空隙假設    它的玩家在抱怨/缺什麼 → 我的差異鉤子候選
```

三張表直接餵下游：空隙假設 → `gdd-positioning.md` 的競品對照表與一句話；借鑑清單 → `gdd-ideation.md` 的機制移植原料。**拆到能填出競品對照表就停**。

## 常見坑

- **「我玩過 500 小時」當拆過**：沒有寫下來的循環圖與時間軸就沒有拆解——時數是玩家經驗，不是設計輸入。
- **拆表面不拆結構**：記了 100 個功能，說不出樂趣引擎——回到三個問題自檢。
- **借鑑清單變抄襲清單**：搬的是「為什麼成立」的結構，不是數值和皮——皮會被認出來，結構不會。
- **只拆頭部作**：頭部作的資源量你複製不起——同量級的成功小品才是可執行的參照。
- **分析癱瘓**：拆了 10 款還不動手——2-3 款、三張表、進漏斗（`gdd-ideation.md` 的三關）。
