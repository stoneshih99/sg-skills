# 常見熱點對照

量測指向某個區域後，用這張對照表找典型肇因。每類都列「症狀 → 常見原因 → 對策方向」（手法細節見 `perf-optimization-playbook.md`）。

## 渲染（GPU / 提交端）

**症狀**：GPU 時間高、draw call 數量大、降解析度就變快。

- **Draw call 過多**：每個物件單獨提交。→ 合批（相同材質靜態合併、instancing 畫大量同型物件）。
- **Overdraw**：大面積半透明疊層（粒子、UI 背景）反覆填色，行動裝置頭號殺手。→ 減少透明層數、粒子貼圖裁小、UI 不透明區塊用不透明材質。
- **材質 / 貼圖切換頻繁**：狀態切換打斷批次。→ 圖集（atlas）、按材質排序繪製。
- **像素負載過重**：高解析 + 重 shader。→ 降 shader 複雜度、動態解析度。
- **陰影與後處理**：常常一項就佔掉半個預算。→ 逐項開關量測，砍到預算內。

## 每幀配置與 GC

**症狀**：週期性 spike（圖上規律的尖刺）、記憶體鋸齒狀起伏。

- **每幀 new**：在 update 內配置（臨時集合、字串拼接、閉包、裝箱）。→ 預先配置、重用緩衝、物件池。
- **字串**：每幀組 UI 文字、拼 log。→ 只在值變化時重建（見 debug-toolkit 的 log_on_change 同思路）、用 StringBuilder 類機制。
- **頻繁生成銷毀**：子彈、粒子、敵人大量 spawn/destroy。→ 物件池。
- 判別法：profiler 看每幀配置量（allocation per frame），目標是**穩態下趨近零**。

## 物理

**症狀**：物理步進時間高、物件多的場景明顯變慢。

- **碰撞對數爆炸**：N 個可碰撞物件兩兩檢測 O(n²)。→ 空間分割（見 `../../game-architecture/references/algo-data-structures.md`）、碰撞層過濾（子彈不撞子彈）。
- **過細的碰撞形狀**：mesh collider 滿場飛。→ 用原始形狀（盒/球/膠囊）近似，精細形狀只給需要的。
- **步進頻率過高 / 子步過多**：高速物體逼出大量子步。→ 高速物體改 raycast/掃掠（見 physics-calculations 的穿隧）。
- **不動的東西在模擬**：靜態場景物被當動態體。→ 標記 static/sleep。

## 邏輯層（CPU）

**症狀**：某系統的 update 時間高、實體數量增加時線性或超線性惡化。

- **每幀全量掃描**：對所有實體做距離檢查、找目標。→ 空間分割查鄰居、事件驅動代替輪詢。
- **複雜度選錯**：熱路徑裡的 O(n²) / 線性查找。→ 對照 `../../game-architecture/references/algo-problem-solving.md` 換演算法或容器。
- **不需要每幀做的事每幀做**：AI 決策、視野檢查、UI 刷新。→ 降頻（每 N 幀）、分幀攤平、髒標記（dirty flag）。
- **快取不友善的資料佈局**：追指標、AoS 掃部分欄位。→ 見 `../../game-architecture/references/data-oriented-layout.md`。

## 載入與串流

**症狀**：進場景卡死數秒、遊戲中切區域 spike。

- **同步載入大資產**：主執行緒讀檔解壓。→ 非同步載入 + 載入畫面/漸進顯示。
- **首次使用成本**：shader 編譯、首次實例化。→ 預熱（loading 時先觸發一次）。
- **一次載全部**：開場把整個遊戲載進記憶體。→ 分區塊串流、按需載入。

## 快速分診表

| 看到什麼 | 先查 |
|----------|------|
| 規律尖刺 | GC / 每幀配置 |
| 不規律大尖刺 | 載入、生成、首次使用 |
| 均值高 + GPU 滿 | draw call / overdraw / 後處理 |
| 均值高 + CPU 滿 | 邏輯全量掃描、物理對數 |
| 實體越多越慢（超線性） | O(n²)：碰撞對、互相找目標 |
