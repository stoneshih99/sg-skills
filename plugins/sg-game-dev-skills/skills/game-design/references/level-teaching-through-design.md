# 用設計教學（不靠文字）

文字教學是設計的失敗補丁：玩家不讀、讀了也不記。好的教學讓玩家「自己發現自己學會了」——這比任何彈窗都牢固。

## 四段教學法

引入任何新機制時，走這四段（可以壓縮在一分鐘內，也可以攤開成整關）：

1. **示範（Introduce）**：在玩家無法失敗的情境下看到機制存在。
   - 例：搆不到的高台上放著發光的道具（暗示：有辦法上去）。
2. **安全練習（Practice safely）**：第一次使用時無懲罰或懲罰極輕。
   - 例：第一個需要二段跳的跳台下面是地面，不是深淵。
3. **加壓應用（Apply under pressure）**：同一機制，加入敵人 / 時限 / 精度要求。
4. **綜合考試（Test in combination）**：與既有機制組合使用，通過才算學會。
   - 例：邊躲彈幕邊用二段跳過斷崖。

## 讓關卡自己說話的工具

- **視覺語言一致**：可互動的東西有固定的顏色/形狀/光。一旦建立，不要背叛（發光的都能抓，就不能有發光但不能抓的）。
- **引導視線**：光源、色彩對比、線條（電纜、血跡、箭頭狀地形）把視線帶向正確方向。玩家看向哪裡，就會走向哪裡。
- **用死路獎勵探索**：走錯的路給小獎勵再引導回頭，探索不白費，玩家下次還敢探。
- **門檻設計（gating）**：不會新機制就過不去的關口，確保進入下一段的玩家都具備前置知識——這讓後面的設計可以放心疊加。
- **安全的失敗**：教學段的失敗要快速重來、損失趨近零。懲罰重的段落玩家會用最保守的方式通過，學不到東西。

## 什麼時候文字可以用

- 按鍵綁定這類純資訊（「按 X 跳躍」）：一次性、出現在需要的當下、可跳過。
- 文字是確認，不是教學：玩家已經做到一次之後，用一行字命名它（「二段跳解鎖！」），幫助形成心智模型。

## 檢查清單

- [ ] 每個新機制有沒有走完四段？（多數教學失敗是跳過第 2 或第 4 段）
- [ ] 把所有教學文字遮住，玩家還過得了這關嗎？
- [ ] 視覺語言有沒有例外？（有例外就要有理由）
- [ ] 教學段的失敗成本是不是趨近零？
- [ ] 新機制引入後，之後的關卡有沒有持續使用它？（教了不用 = 白教，玩家會忘）

## 常見陷阱

- **一次教多個**：同一段落引入兩個新機制，玩家無法歸因「剛剛是哪個起作用」。一段一機制。
- **示範即考試**：第一次遇到新機制就在懸崖邊上，玩家學會的是恐懼不是機制。
- **開發者盲區**：你自己測永遠覺得「這很明顯」。教學段一定要看不知情的人玩，只觀察、不出聲。
- **教學密度前重後空**：前 30 分鐘塞滿教學，之後再無新東西。把機制引入攤開到整個遊戲，節奏見 `level-pacing-curve.md`。
