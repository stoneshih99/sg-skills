# 通用求解策略

面對一個問題，先判斷它屬於哪種「思路」。以下策略由簡到繁，先試上面的，證明不夠再往下換。

## 暴力（Brute Force）

窮舉所有可能，逐一檢查。

- **何時用**：資料規模小、或需要先有一個正確版本當基準。
- **複雜度**：常見 O(n²)、O(2ⁿ)，視組合而定。
- **遊戲情境**：關卡內只有幾十個物件時，直接兩兩比對即可，別過早優化。
- **陷阱**：規模一放大就爆炸；每幀對全場物件兩兩比對是常見效能地雷（改用空間分割，見 `algo-data-structures.md`）。

```
for each a in items:
    for each b in items after a:
        check(a, b)
```

## 貪婪（Greedy）

每一步都選當下看起來最好的，不回頭。

- **何時用**：局部最優能導向全域最優的問題（如區間排程、Huffman、Dijkstra 的鬆弛）。
- **複雜度**：通常 O(n log n)（多半卡在排序）。
- **遊戲情境**：AI 每回合挑「當前收益最高」的行動；資源分配優先給最急迫的單位。
- **陷阱**：貪婪不保證全域最優。需要全域最優時改用 DP 或搜尋。務必先驗證「貪婪選擇性質」成立。

## 分治（Divide and Conquer）

把問題切成獨立子問題，各自解完再合併。

- **何時用**：問題可遞迴拆成同型的、彼此獨立的子問題（合併排序、快速排序、最近點對）。
- **複雜度**：常見 O(n log n)。
- **遊戲情境**：大量物件的空間查詢用樹狀結構遞迴切分；批次幾何運算。
- **陷阱**：合併步驟的成本容易被低估；遞迴深度過大會爆堆疊，必要時改迭代。

## 動態規劃（Dynamic Programming, DP）

有重疊子問題且具最優子結構時，把子問題的解存起來重用。

- **何時用**：子問題會被重複計算（背包、最短編輯距離、路徑計數、技能樹最優配點）。
- **複雜度**：狀態數 × 每個狀態的轉移成本。
- **遊戲情境**：計算「到每格的最小代價」、build 最優化、機率 / 期望值表。
- **兩種寫法**：
  - Memoization（由上而下 + 快取）：直覺，只算到的狀態。
  - Tabulation（由下而上填表）：可控、易估記憶體。

```
memo = {}
function solve(state):
    if state in memo: return memo[state]
    if is_base(state): return base_value(state)
    best = combine(solve(next_state) for next_state in transitions(state))
    memo[state] = best
    return best
```

- **陷阱**：狀態設計不對就整個失效；狀態空間過大時記憶體爆掉（考慮滾動陣列只留必要的前幾層）。

## 回溯（Backtracking）

逐步建構解，走不通就退回上一步換下一條路。

- **何時用**：需要枚舉所有合法組合 / 排列，且能提早剪枝（解謎、關卡生成的約束滿足、擺放問題）。
- **複雜度**：最壞指數級，靠剪枝壓低。
- **遊戲情境**：程序化生成滿足約束的關卡、數獨類謎題求解、AI 的深度決策枚舉。
- **陷阱**：沒有剪枝就退化成暴力；剪枝條件寫錯會漏解或誤剪。

```
function backtrack(partial):
    if is_complete(partial): record(partial); return
    for choice in candidates(partial):
        if not valid(partial, choice): continue   # 剪枝
        apply(partial, choice)
        backtrack(partial)
        undo(partial, choice)                      # 回溯
```

## 雙指針（Two Pointers）

在有序序列上用兩個索引相向或同向移動，把 O(n²) 壓到 O(n)。

- **何時用**：有序陣列找配對 / 區間（找和為定值的兩數、合併兩有序列、去重）。
- **複雜度**：O(n)（前提通常是已排序，排序 O(n log n)）。
- **遊戲情境**：合併排行榜、碰撞的 sweep-and-prune 掃描軸。
- **陷阱**：未排序時前提不成立；邊界（指針交會條件）易寫錯。

## 滑動視窗（Sliding Window）

雙指針的特例，維護一段連續區間並增量更新其統計量。

- **何時用**：連續子區間的最值 / 總和 / 計數（最近 N 秒 DPS、連續 combo 視窗）。
- **複雜度**：O(n)。
- **遊戲情境**：時間視窗內的傷害統計、輸入 combo 偵測、移動平均平滑數值。
- **陷阱**：視窗進出時的增量更新要對稱（加入右端、移除左端），否則統計量會漂移。

## 選擇速查

- 規模小、要正確基準 → 暴力
- 局部最優即全域最優 → 貪婪
- 可獨立遞迴拆分 → 分治
- 重疊子問題 + 最優子結構 → DP
- 枚舉合法組合 + 可剪枝 → 回溯
- 有序序列找配對 / 區間 → 雙指針 / 滑動視窗
