# 2D 投影與格子（Projection, Grids & Depth Sorting）

2D 遊戲的視角、格子、深度排序是**綁在一起的第一週決策**——三者互相決定，選錯任何一個，重做的是全部美術與尋路。這篇管引擎中立的選型與數學；Unity 落地（Isometric Tilemap、Transparency Sort Axis）見 **sg-unity-dev-skills** 的 unity-runtime 2d 家族。

## 視角選型：四種投影 + 一個關鍵岔路

| 視角 | 是什麼 | 適合 | 代價 |
|------|--------|------|------|
| **Top-down（俯視）** | 正上方或帶傾角俯視 | RPG、雙搖桿射擊、模擬 | 立面資訊少（角色只見頭頂或用假透視混搭） |
| **Side view（橫向）** | 正側面 | 平台、格鬥、橫版動作 | 深度只有一層（前後景是假的） |
| **Isometric（斜視 2:1）** | 菱形格斜 45° 俯視 | 策略、模擬建造、CRPG | 美術量大（多朝向）、**深度排序地獄**、玩家方向感偏 45° |
| **2.5D（3D 場景+正交相機）** | 真 3D 幾何、鎖定視角呈現 2D 感 | 想要 iso 外觀但系統複雜 | 3D 管線成本（建模、光影、效能） |

**關鍵岔路——純 2D iso 還是 2.5D**：需要動態光影、視角旋轉、複雜高度差（坡道、立體交錯）→ 用 3D 正交相機，**z-buffer 免費解掉整個排序問題**；要像素風的絕對控制、美術是手繪 sprite、系統單層平面 → 純 2D iso，接受下面兩節的座標與排序成本。這個決策反悔的成本是全部美術資產，立項就定。

**「isometric」的像素現實**：遊戲用的其實是 **2:1 dimetric**（tile 寬:高 = 2:1，邊線斜率 0.5，像素完美無鋸齒），不是數學上的等角 30°——tile 規格照 2:1 定（尺寸與接縫驗收見 `../../game-production/references/art-asset-types.md` 的 Tilemap 節）。

## Grid 選型

| Grid | 適合 | 特性 |
|------|------|------|
| **方格** | 大多數：Rogue、模擬、平台 | 最簡單；斜向移動距離要裁決（√2 成本或禁斜走） |
| **Iso 菱形** | 斜視角的邏輯格 | **邏輯上就是方格**——只是渲染時轉了投影，資料結構完全共用 |
| **六角** | 戰棋、策略 | 六鄰居等距、無斜角爭議；axial 座標系、螢幕拾取較繁 |

## 座標三空間：邏輯永遠不住螢幕座標

**鐵律：iso 只是渲染投影，不是世界結構**。尋路、碰撞、距離、AI 全在 grid/world 空間算——在螢幕空間算距離，被壓扁的 y 軸會騙人（視覺上等距的兩點，邏輯距離差 2 倍）。

```
# grid → screen（2:1 iso 投影）
screen_x = (gx - gy) * tile_w / 2
screen_y = (gx + gy) * tile_h / 2      # tile_h = tile_w / 2

# screen → grid（點擊拾取，先做逆投影再取整）
gx = (sx / (tile_w/2) + sy / (tile_h/2)) / 2
gy = (sy / (tile_h/2) - sx / (tile_w/2)) / 2
```

- **移動速度在 world 空間定義**：直接在螢幕空間移動，縱向會比橫向「感覺快一倍」（y 被壓成一半）——world 空間等速移動，投影後的視覺差就是正確的。
- **有高度（elevation）時的拾取**：螢幕點會命中多個 tile 柱——由高到低逐層做逆投影測試，取第一個命中。
- grid 本身就是空間分割結構（範圍查詢、鄰居掃描直接用格子索引——見 `algo-data-structures.md`）。

## 深度排序（純 2D iso 的主戰場）

- **基準是腳不是中心**：y-sort 用 sprite 的接地點（pivot 在腳底）比排序——用中心點，高的物件會在錯誤時機蓋住別人。
- **排序鍵複合**：`sort_key = (layer, elevation, feet_y)`——橋上橋下這種跨層結構靠 layer 分段，同層內才比 y。
- **大型物件要切**：一棟 3×3 的建築當一張 sprite，角色走到它「後面下方」時必錯——切成 per-tile 直柱各自排序，或至少切前後兩段。
- **多 sprite 組成的角色（身體/武器/裝備）整組一起排**：對外當一個排序單位，對內固定局部順序——否則武器插進別人身體。

## 常見坑

- **邏輯寫在螢幕座標**：距離、速度、尋路全錯還難查——三空間分清楚，iso 只在最後一步投影。
- **用真 30° isometric 畫 tile**：像素鋸齒永遠對不齊——2:1 dimetric。
- **點擊拾取用矩形判定**：菱形 tile 的角落點到隔壁格——逆投影 + 菱形內判定。
- **y-sort 用 sprite 中心**：高物件排序抖動——pivot 統一放腳底，這是資產規格（進美術驗收清單）。
- **為了排序 bug 逐個手調 z**：每加一個物件壞一次——排序規則系統化（複合鍵），不救火。
- **後期才發現需要旋轉視角/動態光影**：純 2D iso 給不了——回到關鍵岔路，這就是立項該選 2.5D 的訊號。
