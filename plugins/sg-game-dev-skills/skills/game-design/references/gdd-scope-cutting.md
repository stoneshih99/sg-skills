# 範圍控制（Scope Cutting）

企畫最常見的死法不是點子爛，是範圍失控。one-pager 的「範圍」欄不是形式——它是整份企畫裡最需要誠實的一欄。

## 原則

- **範圍是設計決策，不是資源清單**：「不做什麼」定義了遊戲是什麼。砍掉的東西讓留下的東西更清楚。
- **先做會證明「好不好玩」的部分**：資源永遠不夠，優先順序 = 風險驗證順序（見 `gdd-risk-assessment.md`）。
- **MVP 是「最小可驗證樂趣」**，不是「最小可出貨版本」：MVP 要能回答「core loop 好玩嗎」，其他都可以醜、可以假。

## 垂直切片 vs 水平切片

- **垂直切片（Vertical Slice）**：做一小段「品質到位」的完整體驗（一關、含美術音效手感）。驗證的是**體驗成不成立**。
- **水平切片（Horizontal Slice）**：所有系統都做但都粗糙（全部關卡白盒、機制齊但無打磨）。驗證的是**結構與量**。
- 選擇：不確定好不好玩 → 垂直切片先；玩法已驗證、擔心內容量與工期 → 水平切片估產能。

## 「不做清單」怎麼寫

差的不做清單：「不做多人」「不做開放世界」（本來就沒人以為你要做）。
好的不做清單砍的是**你真的很想做的東西**：

- 具體：「第一版只有 1 種敵人 AI 行為，不做群體協作」
- 有痛感：「劇情只用文字框，不做過場動畫」
- 有回收條件：「若 core loop 驗證通過且工期剩餘 > 1 個月，才考慮加入 X」

## 砍範圍的優先順序

要砍的時候，照這個順序砍（由先到後）：

1. **內容量**（關卡數、敵人種類、道具數）——最容易後補。
2. **周邊系統**（成就、圖鑑、每日任務）——不影響核心體驗。
3. **打磨層**（動畫過渡、特效層次）——先能玩再好看。
4. **次要機制**——小心：砍到這層要回頭檢查 one-pager 的核心玩法還成不成立。
5. **核心循環**——不可砍。要砍到這層，等於承認企畫要重寫。

## 檢查清單

- [ ] 「不做」清單裡有沒有至少一個你很想做的東西？（沒有 = 沒真的取捨）
- [ ] 每個「要做」項目能不能對應到核心循環或最大風險的驗證？
- [ ] 若工期砍半，你知道先砍哪三個嗎？（現在就寫下來）
- [ ] 有沒有「回收條件」讓被砍的東西在條件成立時回來？

## 常見陷阱

- **「順便做」**：實作 A 時「順便」加 B，範圍在執行期悄悄膨脹。任何不在清單上的東西都要回 one-pager 記一筆。
- **平均用力**：每個系統都做 60 分，結果沒有一個環節能證明遊戲好玩。先讓核心循環到 90 分。
- **把打磨當進度**：core loop 還沒驗證就在調粒子特效，是用忙碌逃避風險。
- **範圍寫完就不看**：範圍欄要在每次里程碑回顧時重讀，膨脹要被看見。
