# 漏斗與留存

兩張最重要的報表：**新手漏斗**（玩家在前 30 分鐘死在哪一步）與**留存曲線**（玩家隔天還回不回來）。先建這兩張，其他報表按需求加。

## 新手漏斗（Onboarding Funnel）

把「安裝 → 成為穩定玩家」拆成一串步驟，看每步流失多少：

```
安裝並首啟          100%
完成教學步驟 1       92%   ← 每一步都該有事件（tutorial_step_done）
完成教學             71%   ← 這裡掉 21%？教學第 N 步出事了
通過第一關           64%
開始第二場 session   38%   ← 最大峽谷常在「第一次離開後回不回來」
通過第一章           22%
```

用法：

- **找最大落差，不是最大數字**：掉最兇的那一步就是下一個要修的（配玩測找「為什麼」，見 `telemetry-data-to-decision.md`）。
- **步驟粒度要夠細**：教學只埋一個「完成」事件，就看不出死在哪一步——教學每步都埋（見 `telemetry-event-design.md`）。
- **分版本比較**：改了教學後，看新版本的同一張漏斗有沒有變好——這是改動驗證的基本形。

## 留存（Retention）

**D1 / D7 / D30 留存**：安裝後第 1 / 7 / 30 天有回來的比例。

- 讀法：**D1 反映第一印象**（新手體驗）、**D7 反映核心循環是否耐玩**、**D30 反映長期目標與內容量**。哪段低就修哪段，別亂槍打鳥。
- 留存是**同期群（cohort）**指標：只比同一天/同一版本進來的玩家，混著算會被老玩家稀釋。
- 曲線形狀比單點重要：健康曲線是「快速下降後趨平」——趨平的高度就是你的穩定核心盤；一路溜滑梯到零代表沒有留下來的理由。

## Session 指標

- **session 長度分佈**（不是平均！雙峰分佈——一堆 3 分鐘 + 一堆 40 分鐘——平均 20 分鐘是幻覺）。
- **session 頻率**：日均場次，對照你的設計意圖（通勤型短高頻 vs 沉浸型長低頻，見 `../../game-design/references/gdd-positioning.md` 的情境）。
- **流失定義**：連續 N 天未登入視為流失（N 依遊戲節奏定，常見 7-14）。流失前最後一個 session 做了什麼，是最值錢的屍檢資料。

## 遊戲內行為報表

- **關卡熱區**：每關的完成率 / 死亡數 / 平均時長排表——難度尖刺一眼可見（對照 `../../game-design/references/level-pacing-curve.md` 的設計意圖）。
- **經濟監控**：貨幣總發行 vs 總回收的日趨勢（source/sink 平衡的營運檢查，見 progression-and-economy 的通膨）；玩家餘額分佈（中位數暴漲 = 通膨進行中）。
- **功能使用率**：各系統的使用人數比例——做了沒人用的系統，是砍掉還是改入口，先看數據再吵。

## 常見陷阱

- **看平均不看分佈**：平均值被極端值綁架；session 長度、餘額、通關時間一律看分佈與中位數。
- **漏斗步驟跨太大**：兩步之間掉 40% 但中間隔了十個行為，等於沒有定位。
- **不分 cohort 比留存**：新版上線後「整體留存上升」可能只是老玩家占比變高。
- **指標好轉就慶祝**：D1 上升的同時 D7 掉了？可能是把「快速篩掉不適合玩家」的教學改成「哄住所有人」——指標要成組看，別單點優化。
